## 2. 模块功能详述

### 2.1 模块①：对话式问数

#### 2.1.1 自然语言提问（F-1.1）

| 项 | 说明 |
| --- | --- |
| 功能描述 | 用户在对话框输入自然语言问题，系统返回数据答案 |
| 输入 | 文本问题，如"上个月华东地区的销售额是多少" |
| 输出 | 结构化答案 + 图表 + SQL 溯源 + 结论摘要 |
| 规则 | 支持追问、支持 @指标 快捷引用、支持上传图片/表格辅助提问（V2） |
| 边界 | 空输入、超长输入（>500 字）、敏感词需拦截提示 |

**支持的问题类型**

| 类型 | 示例 | 处理方式 |
| --- | --- | --- |
| 查数 | 上个月销售额多少 | 指标 + 时间过滤 |
| 对比 | 华东和华南哪个卖得好 | 维度 + 排序 |
| 趋势 | 近 6 个月销售额趋势 | 时间维度 + 图表推荐 |
| 排名 | 销量 Top10 的产品 | 排序 + limit |
| 占比 | 各渠道销售占比 | 维度 + 占比计算 |
| 同比/环比 | 本月同比去年如何 | 复合指标 |
| 归因 | 为什么这个月下滑 | 下钻 + 异常检测（V2） |
| 闲聊/无关 | 今天天气如何 | 拒答 + 引导 |

#### 2.1.2 意图识别与澄清反问（F-1.2）

- **意图分类**：查询 / 对比 / 趋势 / 排名 / 占比 / 同环比 / 归因 / 闲聊
- **原则**：只对"猜错代价高且无法从上下文补全"的情况反问；能从默认值安全推断的，直接出数并在结果中标注口径。

**澄清触发条件**

| 触发条件 | 是否澄清 | 处理 |
| --- | --- | --- |
| 未识别到任何指标 | 必须 | 列出候选指标（受控词表内），提示换一种问法 |
| 指标歧义（命中多个指标且无最长匹配胜出） | 必须 | 列出候选，说明一次只支持一个指标 |
| 显式要求"按 X 看"，但当前指标不支持维度 X | 必须 | 不静默丢弃；提示支持该维度的替代指标，或保留原维度 |
| 说了"分一下 / 拆开看"但未指明维度 | 必须 | 列出当前指标的可用维度 |
| 同环比 + 多个分组维度 | 必须 | 本期只支持整体对比，提示去掉分组或改为分组查询 |
| 闲聊 / 非问数 | 必须（转澄清） | 返回能力提示，不继承上下文 |
| 时间缺失 | **不澄清** | 默认全量区间（不加时间过滤），结论中标注"全量" |
| 相对时间超出数据范围 | **不澄清** | 按数据锚点日裁剪到有数据的区间并提示 |
| 同环比但未给时间 | **不澄清** | 环比取上个月、同比取今年（与 DSL 默认一致） |
| 置信度低于阈值（仅 LLM 模式） | 条件 | 默认阈值 0.75，可配置；离线规则模式不适用 |
| 列级权限拒绝（deny） | **不澄清** | 直接返回无权限，不暴露被拒字段的取值信息 |

**澄清卡片要求**

- 携带稳定的 `clarify_id`、候选列表、以及已识别的部分槽位（维度/时间/排名）；
- 有效期与会话 TTL 一致（默认 30 分钟），过期后需重新提问；
- 用户直接回复候选项名称即可接续（见 2.1.3 `clarify_pick`），无需重述完整问题。

**澄清交互示例**

```
用户：销售额和订单数分别是多少
系统：一次只能查一个指标，请指明你关注哪一个？
      Ⓐ 销售额（gmv）   Ⓑ 订单数（order_cnt）

用户：各大区销售额
用户：那按曲风看
系统：销售额不支持"曲风"维度。可改用「曲目销量」按曲风查看，或保留「按大区」查看。
```

#### 2.1.3 多轮上下文追问（F-1.3）

**改写模式**（按优先级从高到低判定，命中即止）

| 优先级 | 模式 | 触发条件 | 行为 |
| --- | --- | --- | --- |
| 1 | `clarify_pick` 澄清接续 | 上一轮在澄清，本轮输入命中候选项 | 用澄清时已识别的维度/时间 + 本轮选定指标，组装完整 DSL |
| 2 | `followup` 追问 | 本轮能解析出指标，且带追问标记（呢 / 那 / 换成 / 按…看 / 也 / 再） | 本轮显式槽位覆盖，未提及的槽位继承上一轮 |
| 3 | `borrow` 省略 | 本轮解析不出指标，但识别到维度/时间/取值/排序，且带省略标记 | 指标沿用上一成功轮，其余槽位按"显式优先、缺失继承"补全 |
| 4 | `new` 新问题 | 以上均不命中 | 作为全新问题处理，**不继承任何上下文** |
| 5 | `clarify` 澄清 | 仍无法补全 | 返回澄清卡片，不猜测 |

**槽位继承优先级**

| 槽位 | 本轮显式给出 | 无显式 + 有追问标记 | 无追问标记 |
| --- | --- | --- | --- |
| 指标 metric | 用本轮 | 沿用上一成功轮 | 不继承 |
| 维度 dimensions | 用本轮 | 沿用上一轮 | 不继承 |
| 时间 time_range | 用本轮 | 沿用上一轮 | 不继承 |
| 筛选 filters | 用本轮（取值非空时） | 沿用并按可用维度过滤 | 不继承 |
| 排序/条数 order_by/limit | 用本轮 | 沿用 | 不继承 |
| 同环比 compare | 从不继承 | 从不继承 | 从不继承 |

**上下文污染防护**

- 句中无追问标记时一律不继承。例：首轮"各大区销售额"，次轮"今天天气怎么样" → 返回澄清，**不得**补成"今天各大区销售额"。
- 只从**最近一次成功出数**的轮次继承；澄清轮、报错轮、无结果轮不参与。
- 本轮显式要求的维度不被当前指标支持时（如"销售额按曲风看"），不静默丢弃，而是澄清并提示支持该维度的替代指标（曲目销量）。

**指代消解**

"这些国家的销售额" → 取上一轮结果集中 `country` 列的去重取值，生成 `country IN (...)`（最多 50 个）。
取值只来自本会话的结果集快照，不额外查库、不做猜测。

**会话状态约束**

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 空闲过期 TTL | 30 分钟（滑动续期） | 每次访问重置计时 |
| 会话容量 | 500 个（超出按 LRU 淘汰） | 先清过期，再淘汰最旧 |
| 参与改写的轮数 | 最近 5 轮 | 仅影响拼给解析器的历史长度，不影响状态保留 |
| 澄清有效期 | 与 TTL 一致 | 过期后澄清失效，需重新提问 |
| 手动清空 | 结束会话 / `reset()` | 清空上下文，会话 ID 作废 |
| 存储 | `chat_session` / `chat_turn` / `chat_clarify`（元数据库） | 进程重启不丢；TTL 与容量按库内 `expires_at` / `updated_at` 控制 |

TTL 与容量是"时间"和"数量"两个独立上限，任一触发即会话失效；轮数上限只约束历史注入长度，不裁剪已保存的轮次。

**可复现示例**

```
用户：各大区销售额
系统：gmv × region                              [new]
用户：那上个月呢
系统：gmv × region，time_range=last_month        [borrow] 沿用指标与维度，替换时间
用户：换成订单数呢
系统：order_cnt × region，time_range=last_month  [followup] 替换指标，继承维度与时间
```

```
用户：销售额和订单数分别是多少
系统：澄清卡片（候选：销售额 / 订单数）
用户：销售额
系统：gmv（无维度）                              [clarify_pick] 接续澄清并补全
```

```
用户：销售额Top5的国家
系统：gmv × country，limit=5                     [new]
用户：那按城市看
系统：gmv × city，limit=5                        [borrow] 继承 Top5 排序与条数，下钻到城市
用户：这些国家的销售额
系统：gmv × country WHERE country IN (上轮 Top5)   [followup + 指代消解]
```

### 2.2 模块②：语义层管理（核心）

#### 2.2.1 模型管理（F-2.1）

| 项 | 说明 |
| --- | --- |
| 功能 | 定义物理表/宽表的语义包装 |
| 字段 | 模型名、显示名、物理表、主键、join 路径、默认过滤、owner |
| 规则 | join 关系必须显式声明，禁止自动推断 |
| 校验 | 关联字段类型一致、防循环依赖 |

#### 2.2.2 指标管理（F-2.2）

**指标三层结构**

| 层级 | 定义 | 示例 | 表达式 |
| --- | --- | --- | --- |
| 原子指标 | 基础聚合，无时间/维度限定 | 销售额 | `SUM(total)` |
| 派生指标 | 原子 + 时间/修饰词 | 上月销售额 | 本期不实现，同环比由 DSL `compare` 表达 |
| 复合指标 | 指标间运算 | 客单价 | `${gmv}/${order_cnt}` |

**指标字段**：名称、显示名、同义词、类型、表达式、所属模型、可用维度、时间字段、默认过滤、口径描述、owner、状态。

**规则**
- 复合指标必须引用已注册指标，不得重写 SQL
- 指标间引用不得循环
- 指标发布前需审批（见 2.2.5）

#### 2.2.3 维度管理（F-2.3）

| 字段 | 说明 |
| --- | --- |
| 名称/显示名/同义词 | "大区/地区/区域" |
| 所属模型 / 表达式 | 字段或 CASE WHEN 派生 |
| 维度类型 | categorical / time / numeric |
| 层级 | 如 大区 → 国家 → 城市，支持下钻 |
| 枚举值映射 | 华东: [上海,江苏,浙江]，支持同义词 |

#### 2.2.4 同义词/受控词表管理（F-2.4）

- 维护业务术语的**口语说法 → 标准对象**映射
- 支持别名、缩写、错别字（如 "gmv"/"GMV"/"销售额"）
- 用于 NL → DSL 阶段的**词表匹配**（提升召回准确率）
- 支持批量导入/导出

#### 2.2.5 审批与版本管理（F-2.5）

**对象与范围**：模型、指标、维度三类对象统一走同一套版本与审批机制（元数据结构见技术设计文档 8.4）。

**状态机**

```
draft ──submit──▶ pending ──approve──▶ published ──新版本发布──▶ deprecated
  ▲                  │
  └────reject────────┘

published ──rollback（复制目标版本 payload）──▶ draft(v+1) ──submit──▶ ...
```

| 状态 | 可执行动作 | 说明 |
| --- | --- | --- |
| `draft` 草稿 | 编辑、提交、删除 | 未提交前同一对象连续编辑原地覆盖，不刷版本号 |
| `pending` 待审批 | 通过、驳回 | **不可编辑**，须先驳回，避免绕过审计链 |
| `published` 已发布 | 被新版本替代、发起回滚 | 运行时唯一读取的状态 |
| `rejected` 已驳回 | 重新编辑、提交 | 保留驳回意见作为审计记录 |
| `deprecated` 已下线 | 查看、回滚 | 历史版本不物理删除 |

**版本规则**

- 版本号在 `(对象类型, 名称)` 内单调递增；每个版本**不可变**，编辑即产生新版本。
- 发布新版本时，旧的 `published` 自动转为 `deprecated`，且**同一对象同时只能有一个 `published`**（数据库唯一约束兜底）。
- **回滚不是删除**：以目标历史版本的 payload 新建一个 `draft(version+1)`，仍需走审批才生效。
- 支持任意两个版本的结构化差异对比（字段级 added / removed / changed）。

**发布前守卫**

发布前在同一事务内重建一份"候选语义层"并校验：

1. 模型 join 路径可达、无悬空引用；
2. 复合指标引用的子指标均存在且已发布；
3. 指标/维度引用的模型存在；
4. 无循环依赖。

校验失败则整批回滚，线上版本不受影响。

**审计与生效**

- 每个动作（create / edit / submit / approve / reject / rollback / import）写入事件链，记录操作人、时间、意见，可回答"谁在何时改了什么、为什么"。
- 发布即生效：运行时每次请求读取当前 `published` 版本，无需重启服务。
- 变更后自动触发相关评测集重跑（V2），评测结果绑定语义层快照，可定位"哪次发布导致指标回退"。
- 审批人与提交人为同一人时告警（四眼原则，V2 强制阻断）。

#### 2.2.6 数据血缘（F-2.6）
- 指标 → 模型 → 物理表 的血缘链路可视化
- 上游表变更影响面分析

### 2.3 模块③：查询执行

| 功能 | 说明 | 规则 |
| --- | --- | --- |
| F-3.1 DSL→SQL 编译 | 受控查询 DSL 编译为确定性 SQL | 编译不依赖 LLM |
| F-3.2 校验与自修复 | 语法/语义校验，失败回环重写 | 最多重试 2 次 |
| F-3.3 沙箱执行 | 只读账号执行，超时/行数限制 | 超时 30s，行数 10 万 |
| F-3.4 结果缓存 | 相同 DSL 结果缓存 | TTL 按数据更新周期 |

**安全规则（强制）**
- 仅允许 SELECT，禁止 INSERT/UPDATE/DELETE/DROP
- 权限过滤在**编译期**注入，不接受 LLM 生成的 WHERE 权限条件
- 所有执行 SQL 留痕审计

### 2.4 模块④：权限与安全

| 功能 | 说明 |
| --- | --- |
| F-4.1 用户与角色 | 角色：业务用户/分析师/数据工程师/管理员 |
| F-4.2 行级权限 | 按维度值过滤（如仅本大区数据），编译期注入 |
| F-4.3 列级权限/脱敏 | 敏感字段：拒绝访问 / 掩码 / 聚合降维 |
| F-4.4 多租户 | 模型/指标/数据按租户隔离 |
| F-4.5 审计日志 | 记录：用户、问题、DSL、SQL、结果行数、耗时、时间、权限快照、语义层批次号（落 `query_audit`） |

**权限校验流程（编译期强制）**

```
DSL(含指标/维度)
   → 解析涉及的维度与字段
   → 比对当前用户行级规则 → 注入 WHERE 过滤
   → 比对列级规则 → 脱敏/拒绝
   → 输出最终 SQL
```

| F-5.2 评测集管理 | golden Q→DSL/SQL 对，按业务域分组；用例落 `eval_case`，跑批写 `eval_run` / `eval_result` |
| F-5.3 准确率监控 | EX、匹配率、澄清率、拒答率、失败 Top 问题 |
| F-5.4 失败沉淀 | 失败 case → 补同义词/修正语义层/加 Few-shot |

**核心评测指标**

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| EX（执行准确率） | 执行结果与标准答案一致 | ≥ 90% |
| 澄清率 | 触发反问占比 | 观察值 |
| 拒答率 | 无法回答占比 | 越低越好 |
| 平均响应 | 端到端耗时 | P95 ≤ 5s |
| 采纳率 | 结果被采纳/点赞占比 | ≥ 70% |

## 3. 关键用例

### UC-01 业务用户查数
- **角色**：业务用户
- **前置**：已登录，有对应数据权限
- **主流程**：输入问题 → 系统识别意图 → 召回指标/维度 → 校验 → 编译 SQL → 执行 → 返回图表 + 结论
- **异常**：
  - 意图不明确 → 澄清反问
  - 无权限维度 → 提示无权限
  - 编译失败 → 自动修复 2 次后转人工提示

### UC-02 多轮追问
- **主流程**：首轮问"上月销售额" → 用户追问"那华南呢" → 继承指标和时间，切换维度 → 返回结果

### UC-03 指标新增
- **角色**：数据工程师
- **主流程**：创建指标 → 定义表达式/维度 → 提交审批 → owner 审核 → 发布 → 生成版本

### UC-04 权限越权拦截
- **主流程**：无华东权限用户问华东数据 → 编译期检测 → 返回"无该数据权限"

## 6. 异常与边界处理

| 场景 | 处理策略 |
| --- | --- |
| 问题无对应指标 | 提示最接近的指标，引导改用标准问法 |
| 指标准确但维度不支持 | 返回可用维度列表 |
| 时间范围越界 | 提示数据可查范围 |
| SQL 编译失败 | 自动修复 2 次 → 失败转人工工单 |
| 查询超时 | 提示缩小范围/降低粒度 |
| 结果为空 | 提示"该条件下无数据"，建议放宽条件 |
| 敏感问题 | 拒答并记录 |
| 并发过载 | 排队 + 限流提示 |
| 大模型不可用 | 降级为关键词检索+模板查询 |
