```
├───────────────────────────────────────────────────────────────────┤

├───────────────────────────────────────────────────────────────────┤
│  应用层                                                             │
│   ┌────────────┐ ┌────────────┐ ┌────────────┐ ┌────────────┐     │
│   │ 问数服务    │ │ 语义层服务  │ │ 权限服务    │ │ 评测服务    │     │
│   └────────────┘ └────────────┘ └────────────┘ └────────────┘     │
├───────────────────────────────────────────────────────────────────┤
│  核心引擎层（本项目灵魂）                                           │
│   ┌─────────────────────┐   ┌─────────────────────┐              │
│   │ NL→DSL 服务          │   │ DSL→SQL 编译引擎     │              │
│   │ 意图识别/Schema链接   │   │ 确定性编译/权限注入   │              │
│   │ RAG/校验/澄清/自修复  │   │ 缓存/限流             │              │
│   └─────────────────────┘   └─────────────────────┘              │
├───────────────────────────────────────────────────────────────────┤
│  数据层                                                             │
│   语义层元数据存储(PostgreSQL) │ 向量库(Milvus/pgvector)           │
│   缓存(Redis) │ 执行沙箱(只读连接池)                                │
├───────────────────────────────────────────────────────────────────┤
│  外部依赖   大模型(云API/vLLM) │ 数据源(MySQL/Hive/Doris/PG)        │
└───────────────────────────────────────────────────────────────────┘
```

### 1.2 核心设计原则

| 原则 | 说明 |
| --- | --- |
| **受控生成** | LLM 只输出受控 DSL，不直连数据库、不直接写 SQL |
| **两阶段分离** | NL→DSL（概率、LLM）与 DSL→SQL（确定、代码）严格分离 |
| **权限编译期注入** | 权限过滤由引擎注入，不信任 LLM 生成的条件 |
| **可溯源** | 每次回答可回放：问题 → DSL → SQL → 结果 |
| **降级可用** | LLM 不可用时降级为模板/关键词查询 |

## 3. 语义层设计（核心）

### 3.1 DSL 数据模型

```
Model(模型)
 ├─ name, display_name, physical_table, primary_key
 ├─ joins: [ {to_model, type, on:[{from,to}]} ]
 ├─ default_filter
 └─ owner, status

Metric(指标)
 ├─ name, display_name, synonyms[]
 ├─ type: atomic | composite        # derived 本期不实现（见 8.5）
 ├─ expression              # 原子: SUM(x)；复合: ${m1}/${m2}
 ├─ base_metric             # 预留：派生指标的基指标，本期不解析
 ├─ time_dimension          # 该指标的时间字段
 ├─ model                   # 所属模型
 ├─ available_dimensions[]  # 可切分的维度
 ├─ default_filters[]
 ├─ description             # 口径描述
 └─ owner, status, version

Dimension(维度)
 ├─ name, display_name, synonyms[]
 ├─ model, expression
 ├─ dim_type: categorical | time | numeric
 ├─ hierarchy[]             # [大区, 国家, 城市]
 ├─ value_mapping{}         # 华东: [上海,江苏,浙江]
 └─ status

Synonym(词表)
 └─ term → target_object(metric/dimension value), weight
```

### 3.2 语义层 YAML 示例

```yaml
# ---------- 模型 ----------
models:
  - name: fact_invoice
    display_name: 销售事实表
    physical_table: invoice
    primary_key: invoice_id
    owner: 数据工程组
    joins:
      - to_model: dim_customer
        type: many_to_one
        on: [{ from: customer_id, to: customer_id }]

  - name: dim_customer
    display_name: 客户维表
    physical_table: customer
    primary_key: customer_id

# ---------- 指标 ----------
metrics:
  # 原子指标
  - name: gmv
    display_name: 销售额
    synonyms: [营收, 营业额, 销售金额, GMV, revenue]
    type: atomic
    model: fact_invoice
    expression: SUM(invoice.total)
    time_dimension: invoice_date
    available_dimensions: [region, country, genre, artist, month, channel]
    default_filters: ["invoice.status = 'paid'"]
    description: 已支付订单金额合计，不含退款
    owner: 财务部

  # 复合指标（引用其他指标，不写 SQL）
  - name: aov
    display_name: 客单价
    synonyms: [平均订单金额, 单均]
    type: composite
    expression: "${gmv} / ${order_cnt}"
    time_dimension: invoice_date
    available_dimensions: [region, month]
    owner: 财务部

  # 派生指标（时间限定）—— 本期不实现，仅保留结构示意；同环比请用 DSL compare
  # - name: gmv_mom
  #   display_name: 销售额环比
  #   type: derived
  #   base_metric: gmv
  #   time_window: mom

# ---------- 维度 ----------
dimensions:
  - name: region
    display_name: 大区
    synonyms: [地区, 区域, area]
    model: dim_customer
    expression: "CASE WHEN country IN ('上海','江苏','浙江') THEN '华东' ... END"
    dim_type: categorical
    hierarchy: [region, country, city]
    value_mapping:
      华东: [上海, 江苏, 浙江]
      华南: [广东, 福建]

  - name: month
    display_name: 月份
    synonyms: [月度, 按月, 逐月]
    model: fact_invoice
    expression: "strftime('%Y-%m', invoice_date)"
    dim_type: time
    hierarchy: [year, quarter, month]
```

### 3.3 受控查询 DSL（NL 的输出目标）

```json
{
  "metric": "gmv",
  "dimensions": ["region", "month"],
  "filters": [
    { "dimension": "region", "op": "in", "value": ["华东"] },
    { "dimension": "genre", "op": "eq", "value": "Rock" }
  ],
  "time_range": { "type": "relative", "value": "last_3_months" },
  "order_by": [{ "field": "gmv", "direction": "desc" }],
  "limit": 10,
  "compare": null
}
```

**DSL 约束（枚举化，防幻觉）**

| 字段 | 取值约束 |
| --- | --- |
| metric | 必须存在于语义层注册表 |
| dimensions | 必须是该指标 available_dimensions 的子集 |
| filters[].dimension | 必须是该指标 available_dimensions 的子集 |
| filters[].op | `eq / neq / in / gt / lt / between / like` 白名单 |
| filters[].value | **必须落在该维度的受控取值（value_mapping / 枚举）内**，否则编译报错 |
| order_by[].field | 只能是当前 metric 或 dimensions 中的维度 |
| order_by[].direction | `asc / desc` |
| limit | 正整数，上限由数据源 `max_rows` 约束 |
| time_range.type | `relative / absolute` |
| time_range.value | 受控枚举（today/last_7_days/...) 或 ISO 区间 |
| compare | `null / mom / yoy`；**本期只支持无维度分组的整体对比** |

`compare` 语义：以当前 `time_range` 为当期，向前平移一个周期（`mom` 平移 1 个月，`yoy` 平移 1 年）
计算对比期，返回当期值、对比期值、`delta`、`ratio`。分组对比为后续版本。
`compare` **不参与上下文继承**（见 8.11 ③），避免上一轮的同环比被静默带到新问题。

## 4. DSL → SQL 编译引擎

### 4.1 编译流程

```
输入: DSL + 用户上下文(user_id)
 │
 1. 校验(Validate)
 │   ├─ 指标存在? 维度对该指标可用? op 合法? 时间合法?
 │   ├─ 过滤取值在受控词表内? order_by 字段合法?
 │   └─ 不通过 → 返回结构化错误(供 LLM 修复 / 供澄清)
 │
 2. 依赖解析(main模型 + joins)
 │   └─ 根据维度/过滤所涉模型，计算 join 图，生成 FROM/JOIN
 │
 3. 表达式展开
 │   ├─ 原子指标 → 聚合表达式
 │   ├─ 复合指标 → 递归展开为子指标表达式
 │   └─ 派生指标 → 本期不实现（同环比由 compare 在步骤 5 处理）
 │
 4. 权限注入(Injection) ★编译期强制
 │   ├─ 行级: 按 permission_rule(dimension, op, values) 注入 WHERE
 │   └─ 列级: 对无权限字段 → 脱敏/拒绝（deny > aggregate > mask）
 │
 5. 时间处理
 │   └─ 相对时间 → 具体区间；环比/同比 → 窗口对比
 │
 6. SQL 生成(参数化，防注入)
 │
 7. SQL 静态校验
 │   └─ 仅 SELECT / 无危险函数 / 语法校验
 └─ 输出: { sql, used_metrics, used_dims, warnings }
```

### 4.2 编译产出示例

DSL → SQL：

```sql
-- 问题：近3个月华东地区各月销售额 Top10
SELECT
    CASE WHEN c.country IN ('上海','江苏','浙江') THEN '华东' END AS region,
    strftime('%Y-%m', i.invoice_date) AS month,
    SUM(i.total) AS gmv
FROM invoice i
JOIN customer c ON i.customer_id = c.customer_id
WHERE i.status = 'paid'
  AND c.country IN ('上海', '江苏', '浙江')      -- 维度过滤
  AND i.invoice_date >= :start AND i.invoice_date < :end  -- 时间
  AND (CASE WHEN c.country IN ('USA','Canada') THEN '北美' END = :p1)  -- ★权限注入(按维度)
GROUP BY 1, 2
ORDER BY gmv DESC
LIMIT 10;
```

### 4.3 缓存设计

| 缓存对象 | Key | 失效条件 |
| --- | --- | --- |
| DSL→SQL 编译结果 | `sha256(dsl_json + release_id + user_id + perm_hash)` | `release_id` 变更即失效（发布即失效，无需等 TTL） |
| 查询结果 | `sha256(sql_text + data_version + row_limit)` | 数据版本更新（默认 T+1） |
| Schema 召回 | `sha256(norm_question + release_id + top_k)` | 语义层发布或词表变更，最长 1h |
| 会话上下文 | `session:{session_id}` | 滑动 TTL，默认 30min |

失效以**发布批次 `release_id`** 为锚点，而非笼统的"语义层版本"：一次发布是一个原子快照，
避免多对象分别变更时出现半新半旧的缓存。数据结构见 8.11 ④。

## 5. NL → DSL 的 LLM 链路

### 5.1 处理流水线

```
用户问题
  │
  ├─(1) 预处理: 标准化、敏感词、超长截断
  │
  ├─(2) 意图识别: 查询/对比/趋势/排名/占比/同环比/归因/闲聊
  │       └─ 小模型分类器（本地 7B / 微调）
  │
  ├─(3) Schema 召回 (Schema Linking)
  │       ├─ 词表精确匹配（同义词/别名）
  │       ├─ 向量检索 Top-K 指标/维度
  │       └─ 合并去重 → 候选集
  │
  ├─(4) NL→DSL 生成
  │       ├─ 注入: 候选指标/维度定义 + Few-shot + 输出 schema
  │       └─ 强约束: 只能从候选中选，输出 JSON DSL
  │
  ├─(5) 校验与自修复
  │       ├─ 编译引擎 dry-run 校验
  │       └─ 失败 → 把错误回喂 LLM 重写（≤2 次）
  │
  ├─(6) 澄清判定
  │       └─ 槽位缺失/置信度低 → 返回澄清卡片
  │
  └─ 输出 DSL → 交给编译引擎
```

### 5.2 Prompt 结构（示意）

```
[System]
你是数据分析助手，只能使用下列受控指标和维度。
输出必须是 JSON DSL，metric/dimensions 只能从候选中选择。
不确定时输出 {"clarify": "..."}。

[可用指标]
- gmv(销售额): SUM(invoice.total), 维度[region,month,genre]
- aov(客单价): gmv/order_cnt
...

[可用维度]
- region(大区): 值[华东,华南,...]
- month(月份): 时间维度

[历史对话]
用户: 上月销售额
助手: DSL{...}

[当前问题]
近3个月华东各月销售额

[输出 Schema]
{ "metric": str, "dimensions": [str], "filters": [...], "time_range": {...} }
```

### 5.3 关键策略

| 策略 | 作用 |
| --- | --- |
| 受控词表优先 | 精确匹配优先于向量，减少歧义 |
| 限定候选集 | 每次只注入 Top-K 指标/维度，降低幻觉 |
| 输出 JSON schema 校验 | 结构化约束，便于程序校验 |
| Few-shot 动态检索 | 检索相似历史正确样本注入 |
| 温度调低（0~0.2） | 提升稳定性 |
| 澄清优先于猜测 | 歧义时反问，不硬答 |
| 缓存 | 相同问题直接命中 |

### 5.4 自修复循环

```
DSL → 编译校验失败
  → 错误信息(结构化): {"error":"dimension 'city' not available for metric 'gmv'"}
  → 追加到对话，请求 LLM 修正
  → 重新校验
  → 2 次仍失败 → 返回可读错误 + 建议问法
```

## 6. 执行引擎与安全

### 6.1 沙箱执行

| 项 | 策略 |
| --- | --- |
| 账号 | 只读账号（DB 层授权 SELECT） |
| SQL 白名单 | 仅 SELECT，正则拦截 INSERT/UPDATE/DELETE/DDL/存储过程 |
| 超时 | 30s（可配） |
| 行数 | ≤ 100,000（超出截断并提示） |
| 资源 | 连接池隔离 + 查询队列 + 限流 |
| 危险项 | 禁用 `INTO OUTFILE`、`LOAD_FILE`、系统表写操作 |

### 6.2 权限模型

```
用户 → 角色 → 权限规则（表结构见 8.6 permission_rule）
行级规则: { subject_type, subject_id, dimension, op, values }
列级规则: { subject_type, subject_id, field, action: deny|mask|aggregate }
```

编译期 `PermissionInjector` 根据当前用户规则改写 SQL，**不经过 LLM**。
用户级与角色级规则并集生效；同行级多规则 AND 合并；列级冲突 `deny > aggregate > mask`。

## 8. 元数据数据模型

### 8.1 设计约定

| 约定 | 说明 |
| --- | --- |
| 多租户 | 业务表统一带 `tenant_id`；MVP 固定为 `'default'`，V2 开启隔离时无需改表 |
| 时间 | 统一 `TIMESTAMPTZ`；业务时间与系统时间分开（`biz_date` / `created_at`） |
| 版本 | 语义层对象**不可变**，版本号在 `(tenant_id, obj_type, name)` 内递增 |
| 软删除 | 用 `status='archived'` 表达，不做物理删除（审计与回滚需要） |
| JSON 边界 | 需要索引/约束的字段建列；对象异构定义放 `payload JSONB` |
| 命名 | 表名单数，外键统一 `<实体>_id` |

数据分六个域：**语义层元数据 → 权限 → 会话 → 审计 → 评测 → 反馈/词表**。

### 8.2 实体关系概览

```
tenant ─┬─ app_user ─┬─ user_role ── role
        │            └─ chat_session ─┬─ chat_turn ── feedback
        │                             └─ chat_clarify
        ├─ data_source
        ├─ semantic_release ── semantic_object ── semantic_event
        │                              └── semantic_embedding
        ├─ permission_rule
        ├─ semantic_term
        ├─ query_audit
        └─ eval_case ── eval_run ── eval_result
```

### 8.3 组织、角色与数据源

```sql
CREATE TABLE tenant (
  tenant_id    VARCHAR(64) PRIMARY KEY,
  name         VARCHAR(128) NOT NULL,
  status       VARCHAR(16) NOT NULL DEFAULT 'active',   -- active|disabled
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE app_user (
  user_id      VARCHAR(64) PRIMARY KEY,
  tenant_id    VARCHAR(64) NOT NULL REFERENCES tenant(tenant_id),
  display_name VARCHAR(128),
  email        VARCHAR(256),
  status       VARCHAR(16) NOT NULL DEFAULT 'active',
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE role (
  role_id      BIGSERIAL PRIMARY KEY,
  tenant_id    VARCHAR(64) NOT NULL,
  code         VARCHAR(32) NOT NULL,     -- business_user|analyst|data_engineer|admin
  name         VARCHAR(128) NOT NULL,
  UNIQUE (tenant_id, code)
);

CREATE TABLE user_role (
  user_id  VARCHAR(64) REFERENCES app_user(user_id),
  role_id  BIGINT      REFERENCES role(role_id),
  PRIMARY KEY (user_id, role_id)
);

-- 一个语义域绑定一个数据源及其方言，支撑第 4.2 节的方言适配层
CREATE TABLE data_source (
  ds_id        BIGSERIAL PRIMARY KEY,
  tenant_id    VARCHAR(64) NOT NULL,
  name         VARCHAR(128) NOT NULL,
  dialect      VARCHAR(16) NOT NULL,     -- sqlite|postgres|mysql|hive|doris
  dsn_ref      VARCHAR(256) NOT NULL,    -- 只存密钥引用，不存明文
  readonly     BOOLEAN NOT NULL DEFAULT true,
  max_rows     INT NOT NULL DEFAULT 100000,
  timeout_ms   INT NOT NULL DEFAULT 30000,
  status       VARCHAR(16) NOT NULL DEFAULT 'active',
  UNIQUE (tenant_id, name)
);
```

### 8.4 语义层元数据（版本化）

原设计把模型/指标/维度拆成三张表并各带 `name TEXT UNIQUE` + `version INT`，导致**同一对象存不下多个版本**。现改为**统一版本化对象表 + 发布批次 + 事件链**：

```sql
-- 发布批次：一次发布把多个对象切到线上，提供原子快照号（缓存失效与评测回溯的锚点）
CREATE TABLE semantic_release (
  release_id    BIGSERIAL PRIMARY KEY,
  tenant_id     VARCHAR(64) NOT NULL,
  label         VARCHAR(64) NOT NULL,          -- 如 2026-10-20.1
  status        VARCHAR(16) NOT NULL DEFAULT 'draft',  -- draft|published|superseded
  note          TEXT DEFAULT '',
  created_by    VARCHAR(64),
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  published_at  TIMESTAMPTZ,
  UNIQUE (tenant_id, label)
);

CREATE TABLE semantic_object (
  object_id      BIGSERIAL PRIMARY KEY,
  tenant_id      VARCHAR(64)  NOT NULL,
  obj_type       VARCHAR(16)  NOT NULL,        -- model|metric|dimension
  name           VARCHAR(128) NOT NULL,
  version        INT          NOT NULL,
  status         VARCHAR(16)  NOT NULL,        -- draft|pending|published|rejected|deprecated
  payload        JSONB        NOT NULL,        -- 各类型异构字段，见 8.5
  owner          VARCHAR(128) DEFAULT '',
  created_by     VARCHAR(64)  NOT NULL,
  created_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
  submitted_by   VARCHAR(64)  DEFAULT '',
  submitted_at   TIMESTAMPTZ,
  reviewed_by    VARCHAR(64)  DEFAULT '',
  reviewed_at    TIMESTAMPTZ,
  review_comment TEXT         DEFAULT '',
  release_id     BIGINT       REFERENCES semantic_release(release_id),
  prev_version   INT,                          -- 回滚/派生来源，便于追溯链
  UNIQUE (tenant_id, obj_type, name, version)
);

-- 不变式：每个对象同时只能有一个线上版本，由数据库兜底而非代码自觉
CREATE UNIQUE INDEX uq_semantic_published
  ON semantic_object (tenant_id, obj_type, name) WHERE status = 'published';
CREATE INDEX idx_semantic_pending
  ON semantic_object (tenant_id, status) WHERE status = 'pending';
CREATE INDEX idx_semantic_lookup
  ON semantic_object (tenant_id, obj_type, name, version DESC);

-- 审计事件链：一次动作一行，永不更新
CREATE TABLE semantic_event (
  event_id    BIGSERIAL PRIMARY KEY,
  tenant_id   VARCHAR(64) NOT NULL,
  obj_type    VARCHAR(16) NOT NULL,
  name        VARCHAR(128) NOT NULL,
  version     INT NOT NULL,
  action      VARCHAR(16) NOT NULL,   -- create|edit|submit|approve|reject|rollback|import|deprecate
  actor       VARCHAR(64) DEFAULT '',
  comment     TEXT DEFAULT '',
  request_id  VARCHAR(64),            -- 串联同一请求内的多对象操作
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_event_obj ON semantic_event (tenant_id, obj_type, name, version, event_id);
```

> 不再需要独立的 `semantic_model` / `semantic_metric` / `semantic_dimension` / `semantic_join` / `semantic_approval` 表：
> 对象字段进 `payload`，join 关系属于模型 payload 的一部分，审批状态即 `status` 列，审批轨迹即 `semantic_event`。

### 8.6 权限规则

```sql
CREATE TABLE permission_rule (
  rule_id      BIGSERIAL PRIMARY KEY,
  tenant_id    VARCHAR(64) NOT NULL,
  subject_type VARCHAR(8)  NOT NULL,     -- user|role
  subject_id   VARCHAR(64) NOT NULL,     -- user_id 或 role code
  rule_type    VARCHAR(8)  NOT NULL,     -- row|column
  dimension    VARCHAR(128),             -- 行级：语义维度名
  field        VARCHAR(128),             -- 列级：语义/物理字段名
  op           VARCHAR(16),              -- eq|neq|in|gt|lt|between|like
  values       JSONB,                    -- 行级取值（必须落在受控词表内）
  action       VARCHAR(16) NOT NULL,     -- filter|deny|mask|aggregate
  priority     INT NOT NULL DEFAULT 100,
  enabled      BOOLEAN NOT NULL DEFAULT true,
  created_by   VARCHAR(64),
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  CHECK ( (rule_type = 'row'    AND dimension IS NOT NULL AND op IS NOT NULL AND action = 'filter')
       OR (rule_type = 'column' AND field IS NOT NULL AND action IN ('deny','mask','aggregate')) )
);
CREATE INDEX idx_perm_subject ON permission_rule (tenant_id, subject_type, subject_id) WHERE enabled;
```

**判定优先级（必须与 4.1 步骤 4 一致）**

1. 用户级规则与角色级规则**并集生效**；同一维度多条行级规则用 **AND** 合并（取交集）。
2. 列级冲突按 `deny > aggregate > mask` 处理；命中 `deny` 直接返回无权限，不做降级。
3. 行级过滤由编译引擎注入，**不接受 LLM 输出**；`values` 不在受控词表内视为编译错误，不静默丢弃。

### 8.11 关键不变式

**① 发布事务**（保证"发布即生效"且不出现两个线上版本）

```sql
BEGIN;
UPDATE semantic_object SET status = 'deprecated'
 WHERE tenant_id = :t AND obj_type = :o AND name = :n
   AND status = 'published' AND version <> :v;
UPDATE semantic_object SET status = 'published', release_id = :r
 WHERE tenant_id = :t AND obj_type = :o AND name = :n
   AND version = :v AND status = 'pending';
UPDATE semantic_release SET status = 'published', published_at = now() WHERE release_id = :r;
COMMIT;
```

发布前必须在同一事务内做一次"候选语义层"一致性校验（join 可达、复合指标引用存在、无循环依赖）；
校验失败整批回滚，线上版本不受影响。

**② 对象状态机**

```
draft ──submit──▶ pending ──approve──▶ published ──新版本发布──▶ deprecated
  ▲                  │
  └────reject────────┘        published ──rollback(复制为新 draft)──▶ draft(v+1)
```

禁止：`pending` 直接编辑（须先驳回）；`rejected` 直接发布。

**③ 上下文继承优先级**（对应功能文档 2.1.3）

| 槽位 | 本轮显式给出 | 无显式 + 有追问标记 | 无追问标记 |
| --- | --- | --- | --- |
| metric | 用本轮 | 沿用上一成功轮 | 不继承（按新问题处理） |
| dimensions | 用本轮 | 沿用上一轮 | 不继承 |
| time_range | 用本轮 | 沿用上一轮 | 不继承 |
| filters | 用本轮（取值非空时） | 沿用并按可用维度过滤 | 不继承 |
| order_by / limit | 用本轮 | 沿用 | 不继承 |
| compare | 从不继承 | 从不继承 | 从不继承 |

显式要求的维度不被当前指标支持时，**不静默丢弃**：返回澄清并提示支持该维度的替代指标。

**④ 缓存键与失效联动**

| 对象 | Key | 失效条件 |
| --- | --- | --- |
| DSL→SQL | `sha256(dsl_json + release_id + user_id + perm_hash)` | `release_id` 变更即失效 |
| 查询结果 | `sha256(sql_text + data_version + row_limit)` | 数据版本更新（默认 T+1） |
| Schema 召回 | `sha256(norm_question + release_id + top_k)` | 语义层发布或词表变更 |
| 会话热态 | `session:{session_id}` | 滑动 TTL，默认 1800s |

### 8.12 原型（SQLite）映射

当前可运行原型为 SQLite，是目标结构的**子集**：类型差异如下。发布批次已落地
（`semantic_release` + `semantic_object.release_id` / `prev_version`），但仅单租户
（`tenant_id` 固定 `default`，隔离逻辑未启用）。

| PostgreSQL | SQLite 原型 | 说明 |
| --- | --- | --- |
| `JSONB` | `TEXT`（存 JSON 字符串） | 读写时序列化/反序列化 |
| `TEXT[]` / `JSONB` 数组 | `TEXT`（JSON） | 同义词、可用维度等 |
| `TIMESTAMPTZ` | `TEXT`（ISO8601） | `datetime.now().isoformat()` |
| `BIGSERIAL` | `INTEGER PRIMARY KEY AUTOINCREMENT` | — |
| `vector(1024)` + HNSW | 不建表 | 离线用字符 n-gram / 词表精确匹配 |
| 按月分区 | 不分区 | 数据量小，后续迁移时再分区 |

已落地的表：`semantic_release`、`semantic_object`、`semantic_event`、`chat_session`、
`chat_turn`、`chat_clarify`、`query_audit`、`eval_case`、`eval_run`、`eval_result`。
未落地的表（`permission_rule`、`tenant` / `app_user` / `role` / `user_role`、`data_source`、
`semantic_term`、`feedback`）为本文档定义的目标结构，按里程碑逐步实现；原型阶段对应能力
分别由 `permissions.yaml`（权限规则）、YAML 同义词（词表）承担。

```jsonl
 "expect_dsl":{"metric":"order_cnt","dimensions":["region"]},"tags":["multiturn"]}
```

字段：
- `question`：当前问句
- `setup`：多轮评测时，前置轮次数组（依次执行于同一会话）
- `expected_dsl`：期望 DSL 子集（要求实际 DSL 包含期望的所有键值，不要求完全一致）
- `expected_sql`：期望 SQL，执行后比对多重集结果
- `expected_rows`：期望结果行（JSON 数组）
- `expect_status`：期望状态（`ok`/`clarify`/`denied`）
- `domain` / `tags`：分组与标记（如 `["multiturn","security"]`）
- `tolerance`：数值容差，默认 0.01
- `user`：执行该用例的身份（默认 `alice`；安全用例用 `bob` 验证越权拦截）

> **原型落地**：JSONL 仅作为**导入格式**，导入后落 `eval_case` 表（`setup` → `setup_turns`、`user` → `user_id`，
> 按 `(question, setup_turns, user_id)` 去重并打 `src:<文件名>` 标签）；跑批时写 `eval_run`（批次汇总）
> 与 `eval_result`（逐条结果），评测批次与语义层 `release_id` 绑定，可按批次回溯。

### 11.2 评测指标与判定

| 指标 | 判定方式 |
| --- | --- |
| DSL 准确率 | 期望 DSL 为**子集**，实际 DSL 需包含其全部键值（不要求完全相等，允许额外默认项） |
| EX（执行准确率） | 实际 SQL 与期望 SQL 分别执行，结果做**多重集比对**（忽略行/列顺序，数值容差 `tolerance`） |
| 编译成功率 | DSL 能成功编译为 SQL |
| 自修复成功率 | 首轮失败后修复成功比例 |
| 上下文改写准确率 | 多轮用例（带 `setup`）中，改写后的 DSL 命中 `expected_dsl` 的比例 |
| 越权拦截率 | 安全用例中，越权请求返回 `denied` 且 SQL 不含被禁维度/列的比例（目标 100%） |
| 上下文污染率 | 独立新问题被误继承上一轮槽位的比例（目标 0） |

### 11.3 迭代闭环

```
评测失败 → 归因(召回错/DSL错/口径错/复杂问题)
  ├─ 召回错 → 补同义词/调阈值
  ├─ DSL错  → 加 Few-shot / 调 Prompt / 微调
  ├─ 口径错 → 修正语义层指标定义
  └─ 复杂问题 → 内置复合指标 / 转人工
       ▼
   回归评测 → 上线
```

## 12. 技术风险与缓解

| 风险 | 缓解 |
| --- | --- |
| LLM 输出不稳定 | 温度 0、JSON schema 强制、dry-run 校验 |
| Schema 召回不准 | 语义层压缩候选空间 + 词表精确匹配优先 |
| 复杂查询无法覆盖 | 复合指标内置 + 模板兜底 + 转人工 |
| 语义层与数仓漂移 | 版本管理 + 血缘 + 变更触发回归评测 |
| 大模型成本高 | 分级模型 + 缓存 + 私有化推理 |
| 权限漏洞 | 编译期注入 + 越权回归测试 |
