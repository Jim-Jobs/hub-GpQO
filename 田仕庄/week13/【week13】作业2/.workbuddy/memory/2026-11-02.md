## 修复「页面查询 Failed to fetch」（v7，94/94 全绿）

- 定位方法（关键）：先用 curl 直连验证服务端本身——带浏览器式 header 跑完整 SSE 得到 HTTP 200 完整事件流，
  连续两次请求 200、并发第二路正确 409 → **服务端没问题**，问题在浏览器→服务连接层，
  而前端原样抛出网络层错误导致完全无法定位。以后遇到前端网络错误，先 curl 排除服务端再查浏览器侧
- 两个真实缺陷：①**缺 CORS 中间件**——跨域场景（预览面板 iframe / Vite dev 直连）浏览器拦截后
  一律表现为 `TypeError: Failed to fetch`；②**SSE 无心跳**——空闲期无数据，代理/浏览器可能判定连接断开
- 修复：CORSMiddleware（allow_origins=*，无凭证，本地只读服务放开无风险）；SSE 每 15s 发 `: ping`
  注释帧保活（前端按空行切帧、无 data 自动忽略），总超时改为**累计空闲**判定（心跳不重置计时）；
  api.js 把网络错误翻译为含排查步骤的中文提示并区分 `file://` 打开场景；App.vue 加载即健康检查，
  失败时顶部横幅给 3 步排查 + "重新检测"按钮；main() 捕获 create_app 异常与端口占用给出可执行提示
- 坑：file:// 双击打开 dist/index.html 时（base './' 让页面能渲染）fetch 相对路径必然失败，
  这是"页面能开但查询失败"的高频成因，前端必须显式检测并提示
- 测试：test_web.py 13 → 16 项（新增 CORS 跨域预检/心跳保活/超时释放锁），全量 94（90 离线 + 4 集成）

- 用户「再次执行3」= 重跑页面响应速度优化轮。先确认环境：GLM key 已续期，上次遗留的 401 解除，
  集成 4 项复核通过（全量 101 = 97 离线 + 4 集成）
- 基准实测（3 题 × 2 次，真实 GLM，默认 nocache）：极速首 token 1.77s / 总 2.56s；
  严谨 3.31s / 4.11s。与 v6（1.85s / 3.48s）持平，LLM 往返已接近下限
  （write_query ~1.2s + generate_answer 首 token ~0.5s + 流式 ~1s）；严谨难题 6~7s 中
  评审→改写→复审回路占 3.7s，属质量取舍
- **发现比"慢"更严重的缺陷**：`curl | head` 中途断开后 `_chat_lock` 永久泄漏，之后所有查询 409。
  根因：Starlette 在线程池迭代同步生成器，取消无法传导到阻塞的 `queue.get`，
  生成器 finally 永不执行（日志缺 `chat stream closed`）；background 在流异常时也不执行
- 修复：幂等 `_LockGuard`（worker finally 必执行 + 生成器 finally + BackgroundTask 三处释放）
  + 未启动(5s)/超时自愈换锁；旧 guard 因锁实例变更自动失效，不会误放新锁。实测断开后下一次请求 200
- **问答缓存**：`_AnswerCache`（TTL 600s / LRU 64，`WEB_CACHE_TTL`/`WEB_CACHE_SIZE`），
  key = 问题 + fast + 会话历史（多轮不串答案），只缓存成功且有回答的链路；命中不占锁不调 LLM，
  直接回放 SSE（node 耗时置空，done 带 `cached`/`origin_elapsed`），前端显示「⚡ 缓存命中 · 原耗时 Xs」。
  命中实测首 token / 总耗时 0.00~0.01s。基准默认 `nocache`，`--cache` 才允许命中
- 前端修复：`done` 事件若 rAF 缓冲未上屏，兜底完整 answer 与缓冲 token 叠加会让回答出现两遍
  → done 先 flush 再兜底；等待计时 100ms→200ms 减少重渲染
- 同步：README/AGENTS/TEST_REPORT 数字 94→101、90→97、test_web 17→24；.env.example 加
  WEB_CACHE_*；bench_web 加 `--cache`；新增 7 项测试（3 锁 + 4 缓存）；dist 已重建并删回 node_modules
- 经验：客户端断开类问题必须用「必执行的 worker finally」兜底释放资源，
  不能只依赖生成器 finally / background；性能基准要能绕过缓存，否则重复题目数据失真
