# 技术踩坑记录

本文件记录在 ccgp（中国政府采购网）上做 ESG 招投标数据采集时踩过的坑与已验证的结论。
改动任何脚本逻辑前先读这里，能省掉大量试错。

## 一、反爬与访问

### ccgp 的 WAF 对非浏览器请求直接拒绝

`curl` 或裸 `requests` 请求 `www.ccgp.gov.cn` 返回 **403**，请求
`search.ccgp.gov.cn/bxsearch` 返回一个 2.9KB 的"您的访问过于频繁"页面。
换 UA、加 Referer、带 Cookie 都无效。**唯一可靠方式是用 Playwright 驱动真实 Chromium。**

### 首次请求前要先访问首页

直接打开搜索页有概率被判频次拦截。先 `goto("https://www.ccgp.gov.cn/")` 停留 1.5 秒
养出 cookie，再进搜索页，成功率明显提高。

### 限速参数实测

| 间隔 | 结果 |
|---|---|
| 无间隔连续请求 | 第 2 个请求即超时/拦截 |
| 1.2–2.2 秒 | 48 条详情无阻断，速率约 29 条/分钟 |
| 2.0–3.2 秒 | 稳定，推荐默认值 |
| 并发 3 个页面 | 立即触发限流，比串行更慢 |

结论：**必须串行**。脚本内置退避重试（10s / 18s / 26s / 34s），触发后通常能自愈。
详情页抓取速率约 25–30 条/分钟，可作为估算工期的基准。

### 全量抓取实测（2024-11 ~ 2026-11，20 个关键词 × 3 个自然年）

| 阶段 | 量级 | 耗时 | 备注 |
|---|---|---|---|
| 列表检索 | 2976 条唯一公告（原始 3161） | 25 分钟 | 224 次请求、30 次限流，全部靠退避自愈 |
| 详情抓取 | 1290 条中标/成交公告 | 约 50 分钟 | 24.5 条/分 |

关键词命中量差异极大：`碳排放` 732 条、`绿色低碳` 700 条、`温室气体` 255 条，
而 `ESG` 仅 31 条、`绿色工厂` 6 条、`气候投融资` 28 条。长尾词容易撞上连续限流，
日志出现「触发限流, 退避 34s」连着 4 轮属正常，不要误判为死循环而中断。

`--no-detail` 抓完列表后，**补抓详情必须加 `--from-cache`**，
否则会为了拿详情重新跑一遍 25 分钟的列表检索。缓存按公告 id 存于 `cache/detail/<id>.txt`，
中断后重跑自动续，不会重复请求。

## 二、页面结构

### 检索页

```
https://search.ccgp.gov.cn/bxsearch
  ?searchtype=1&page_index=1&bidSort=0&buyerName=&projectId=&pinMu=0
  &bidType=0&dbselect=bidx&kw=<关键词>
  &start_time=2025%3A01%3A01&end_time=2025%3A12%3A31
  &timeType=6&displayZone=&zoneId=&pppStatus=0&agentName=
```

- 日期用 `%3A` 编码冒号，格式 `YYYY:MM:DD`
- `timeType=6` 表示自定义区间
- **每页固定 20 条**

### 检索是"标题检索"，不是全文

页面明确标注"标题检索"。因此：

- 单一关键词召回很低。`ESG` 在 2025 全年只有 **16 条**，`双碳` 有 **110 条**
- 必须用关键词矩阵（`taxonomy.json` 的 `search_keywords`，20 个词）逐词检索后去重
- 长短语（如"碳排放管理体系建设"）几乎必然 0 条，用短词组合

### 查询跨度超过 1 年会静默返回 0 条

**这是最隐蔽的坑**：接口不报错、不返回错误页、限流计数也不增加，
日志看起来一切正常，结果就是空的。实测：

| 区间 | 跨度 | 结果 |
|---|---|---|
| 2024-11-01 ~ 2025-10-31 | 365 天 | 17 条 ✓ |
| 2025-11-01 ~ 2026-10-31 | 365 天 | 13 条 ✓ |
| 2024-11-01 ~ 2026-11-24 | 754 天 | **0 条** ✗ |

因此 `ccgp_crawler.py` 的 `split_by_year()` 会无条件把用户传入的区间按自然年切开，
再逐段查询后合并。改这块逻辑时不要图省事传整段区间。

排查经验：如果某个关键词命中数是 0，先怀疑区间跨度，再怀疑关键词本身。

### 列表项结构

```html
<ul class="vT-srch-result-list-bid">
  <li>
    <a href="详情页URL">标题（关键词被 <font color="red"> 高亮包裹）</a>
    <p>正文前 100 字摘要</p>
    <span>2025.12.11 18:10:51 | 采购人：xxx | 代理机构：xxx
          <br><strong>中标公告</strong> | 河南 | <strong></strong></span>
  </li>
</ul>
```

坑点：
- 标题里的 `<font>` 标签会把词切断，须用 `get_text("", strip=True)` 再压空白
- 总数文案是 `共找到 110 条内容`，但**数字常被 `<span>` 包裹**，
  正则 `共找到\s*([\d,]+)\s*条` 匹配不到，需写成 `共找到[\s\S]{0,200}?([\d,]+)\s*条`
- 每项 `span` 里第二个 `<strong>` 是空的，取公告类型时要过滤空值

### 详情页正文容器

`div.vF_detail_content`（少数页面为 `div.vF_detail`）。

## 三、表格必须先压行再取文本

**这是金额解析失败的头号原因。**

公告的关键信息（供应商名称、中标金额）放在 `<table>` 里。若直接把整页 `get_text()`，
表格会按单元格顺序拍平，列与列的对齐关系彻底丢失：

```
供应商名称/供应商地址/供应商编码/北京中创碳投科技有限公司/北京市.../91110101...
```

金额与供应商完全错配。正确做法是在 `get_text()` 之前，把每个 `<tr>` 压成一行，
用 ` || ` 分隔单元格：

```
供应商名称 || 供应商地址 || 中标（成交）金额 || 备注
北京中创碳投 || 北京市... || 675000 ||
```

这样下游才能按"表头列索引 → 数据行同列值"取值。

**另一个必踩的坑**：压行时如果过滤空单元格（`[c for c in cells if c]`），
表头 12 列、数据行因有空值只剩 6 列，索引全部错位，金额永远取不到。
**必须保留空字符串占位。**

## 四、中标金额的七种写法

同一个字段，全国数千家代理机构各写各的：

| 形态 | 实例 | 解析方式 |
|---|---|---|
| 表格列 | 表头"中标金额"，数据行 `675000` | 表头定位列索引 |
| 单位前置 | `成交金额(万元)：27` | 单位在标签括号内 |
| 单位后置 | `中标（成交）金额：220.0000000（万元）` | 单位在数值括号内 |
| 模板噪声 | `金额： （可填写下浮率、折扣率或费率）标包【1】29.85万元` | 标签后宽松取样 |
| **标签噪声** | `中标（成交）金额（元）\（%）：2530000.00` | 单位括号后还夹 `（%）`，标签与冒号之间须允许非数字噪声 |
| **表格压行无冒号** | `成交金额 \|\| 2,000,000.00 联系方式 \|\| …` | 压行后用 `\|\|` 分隔、没有冒号，锚点的冒号必须可选 |
| 干扰金额 | 正文另有`代理服务费 0.44775 万元` | 上下文排除 |

三个具体陷阱：

1. **单位必须紧邻数值**。从 `标包【1】29.85万元` 里的 `1` 往后找单位，会跨过 `29.85`
   匹配到 `万元`，把序号 1 读成 1 万元。必须在遇到下一个数字前截止单位查找。
2. **强/弱干扰词要分级**。`代理服务费`、`预算金额`、`最高限价` 出现在标签前 60 字内即作废整段；
   但 `下浮率`、`费率`、`折扣率` 是模板固定提示语（"可填写下浮率、折扣率或费率"），
   离真金额较远，只在紧贴数值前 6 字时才排除。混为一谈会把真金额全部误杀。
3. **无单位的小数值按万元兜底**。咨询项目不会出现 100 元的成交价，若解析出 `27` 且无单位，
   按 27 万元处理。
4. **不能取"最后一个"数字**。表格压行后 seg 里常跟着 `联系方式 || 电话：0731-85387499`，
   若用后续数字覆盖前面的候选，会把电话号码读成 8538 万（真实值 200 万）。
   正确做法：有明确单位的候选优先，同级取**最靠近标签的第一个**。
5. **序号放大要丢弃**。`包1` 的 `1` 经万元兜底变成 1 万元，看似合理实则错误。
   记录 `scaled` 标记，放大后仍 ≤ 2 万的候选直接丢弃。

归一后统一做量级校验：`1000 ≤ 金额 ≤ 50 亿`，超出即丢弃。

实测：早期 48 条小样本金额命中 90%、供应商 94%；补上第 6/7 种写法并修掉 4/5 号陷阱后，
在 335 条真实详情上金额命中 **97%**、供应商 86%，且早期验证样本金额全部保持不变。

## 五、口径陷阱（影响结论正确性，比解析 bug 更致命）

### "双碳"出现在楼名里

中国石油大学（北京）有"双碳"创新国际大厦（科技楼）（实验楼）项目，其下挂着一批公告：

- 基坑支护设计
- 勘察
- 全过程审计
- 清单编制及造价咨询 ← **含"咨询"二字，极易被误判为 ESG 咨询**
- 全过程项目管理咨询服务 ← 同上

这些是基建工程，金额动辄数百万，若不清洗会把高校盖楼的钱算进 ESG 市场规模，
**严重高估**。

判定规则必须是：**基建/货物硬信号优先于"咨询"字样**。命中
`大厦|实验楼|基坑|桩基|施工|造价咨询|全过程项目管理|工程量清单|资产购置|实训|设备采购|租赁`
即判为工程，不接受"咨询"救援。只有无这些硬信号时，含
`ESG|碳核查|碳足迹|平台建设|数字化|指标体系|研究报告` 才判为服务。

### 代理机构名污染（第二批实测发现，误伤面很大）

ccgp 标题的标准写法是「**代理机构名 + 关于 + 真实项目名 + 公告动作**」：

```
台州市天诚工程造价咨询有限公司关于天台县"十五五"双碳战略前期思路研究及规划编制项目中标(成交)结果公告
```

代理机构名里的「造价咨询 / 项目管理 / 工程咨询」会命中工程硬信号，把一单
**双碳规划研究**错误剔除。同类还有「科信联合工程咨询有限公司」「宁波市斯正项目管理
咨询有限公司」。解决：`strip_agent_prefix()` 先切掉「…关于」及其前缀，再做性质判定。

### "清单编制"不能一刀切

`温室气体排放清单编制`、`大气污染物与温室气体融合排放清单编制` 是**双碳核心服务**
（碳核算），而 `工程量清单编制`、`招标清单及控制价编制` 才是工程造价。
最初把「清单编制」放进工程硬信号，一次性误杀了 5 个省级温室气体清单项目。
现在只认 `工程量清单 / 招标清单 / 控制价编制` 三个精准词。

实测：修掉上述两点后，全量 2976 条公告里 `engineering` 从 180 降到 92，
88 个真实咨询服务被救回，核心样本从 752 增至 953。

### 宽口径与分层

用户口径常包含绿色工厂、节能诊断、气候投融资等 L3 周边赛道，不能只统计 L1+L2。
`classify()` 对 L3 里有具体服务标的（含 服务/评价/编制/研究/技术 等词）判 `medium`
纳入核心样本，只有泛泛带「绿色低碳」四字的判 `low` 排除。
报告里用 `tier_dist` 分层展示，读者可自行收窄到只双碳或只 ESG。

### 其他必须剔除的类型

- `上海海事大学…人才培养实训平台`（322 万）— 设备采购
- `长三角双碳创新中心实验基地协约资产购置`（193 万）— 货物采购
- `天津…双碳大厦展陈场地租赁` — 租赁
- `青岛…ESG 联盟年会`、`江苏绿色低碳建筑国际博览会布展` — 会议活动
- `哈尔滨…官员研修班` — 培训

### 关键词误命中的朴素过滤

设备名里也有"碳"：碳粉、碳刷、碳纤维、碳钢管、碳酸。以及园林绿化、绿色通道。
这些放在 `taxonomy.json` 的 `noise_patterns`。

## 六、项目聚合

同一项目会发多条公告：招标公告 → 更正公告 → 中标公告，甚至"（二次）"重发。
不去重的话成交金额会被重复统计。

聚合键 = `采购人前12字 | 归一化项目名`。归一化顺序很关键：

1. **先剥离括号内容**（`（二次）`、`（成交）`、`（北京）`）
2. **再剥离末尾动作词**（中标/成交/结果/公告/公示/更正/废标…）
3. 去掉尾部"的"、所有标点

顺序反了会失败：`上海市双碳示范试点项目的中标（成交）结果公告` 若先剥动作词，
结尾是 `公告` 但前面是 `）`，剥不干净，同一项目会裂成两条。实测修正后
126 条公告聚合成 64 个项目，该项目的 3 条公告正确合并。

动作词表要覆盖 `公开遴选`、`比选`、`磋商`、`失败`、`二次`、`重新`、`第N次`。实测
「《中国体育彩票2026年社会责任报告》编制项目成交公告」与「…公开遴选公告」
因漏掉「遴选」曾裂成两条，补齐后 `n_notices=2` 正确合并。

聚合键也会调用 `strip_agent_prefix()`：同一项目不同公告可能由不同代理机构代发，
剥掉前缀后归一化更稳。展示名另经 `clean_display_title()` 去掉尾部动作词，
报告清单里不再出现「…中标(成交)结果公告」这种长尾巴。

## 七、报告渲染

### 不要用境外 CDN

初次实现用 `<script src="https://cdn.jsdelivr.net/npm/echarts...">`，
Playwright 打开时报 `ERR_CONNECTION_RESET`、`echarts is not defined`，图表全空白。
已改为把 `assets/echarts.min.js`（1MB）直接内嵌进 HTML，产出真正的单文件报告。

### 图表可读性

- 分层金额量纲可能差 20 倍（双碳 6000 万 vs ESG 300 万），单轴柱状会让小层消失 → 用双 Y 轴
- 行业分布政府类常占 70%+，饼图会吞掉细分 → 改用横向条形
- 价格基准用普通柱状 + markPoint 会遮挡柱体 → 改用 P25–P75 范围条 + 中位数标记

## 八、数据覆盖的边界

只覆盖中国政府采购网（中央 + 地方分网）公开公告。**不含**：

- 国企/央企自主采购平台（如国家能源集团、中石油电子采购平台）
- 商业聚合平台（剑鱼、千里马、中策）收录但官方渠道未公开的部分
- 依法非必须招标的企业自主采购

因此报告中的绝对金额应视为**下限**，趋势与结构结论更可靠。这一点必须在报告"方法说明"里写清楚。
