# week11 作业一:SQL Agent 智能问答

基于 chinook 数据库的完整 SQL Agent workflow:自然语言提问,经过 7 步流水线
(数据库解析 → Table 选择 → SQL 生成 → SQL 校验 → SQL 改写 → SQL 执行 → 结果汇总)
返回自然语言答案。前后端完整工程实现,workflow 过程逐步可视化。

参考课件:`week11/code/04_SQL-Code-Agent-Demo/sql-agent.ipynb`(DBParser 与 prompt 风格沿用 demo)。

### 7 步 workflow 与重试循环

1. **数据库解析**(启动时缓存):DBParser 解析 11 张业务表的字段/统计/外键/样例
2. **Table 选择**:LLM 从表清单(schema+外键)中选出相关表,解析失败兜底全表
3. **SQL 生成**:LLM 依据选中表的字段+样例+外键生成单条 SELECT
4. **SQL 校验**:①仅 SELECT/WITH 白名单(拦截 DML/DDL/ATTACH) ②EXPLAIN 走
   sqlite prepare 阶段,语法错误/表不存在/列不存在一次性查出,错误信息可定位
5. **SQL 改写**:校验或执行失败 → 携带具体错误让 LLM 修正 → 回到第 4 步,
   最多 3 次;仍失败则返回友好错误(前端标红)
6. **SQL 执行**:只读连接(mode=ro)执行,结果截断 50 行
7. **结果汇总**:LLM 将查询结果组织为自然语言回答(禁止编造)

SSE 事件协议:`step`(step/name/status/data)逐步推送 + `final`(全量结果)收尾;
每次问答(无论成败)落库 `backend/data/history.db`,点击历史条目直接回放,不重调 LLM。

## 启动

凭据:项目根 `badou2026/.env`(`API_KEY`/`BASE_URL`/`BASE_MODEL`,OpenAI 兼容接口)。

```bash
# 后端(conda 环境 py312;首次需 pip install -r requirements.txt)
cd backend
/opt/miniconda3/envs/py312/bin/python -m uvicorn app.main:app --port 8000

# 前端开发模式(vite proxy /api → :8000;node ≥18,本机可用 nvs 的 v20)
cd frontend && pnpm install && pnpm dev        # http://localhost:5173

# 演示模式(构建产物由 FastAPI 托管,单进程)
cd frontend && pnpm build                      # 产出 dist/
cd backend && /opt/miniconda3/envs/py312/bin/python -m uvicorn app.main:app --port 8000
# 打开 http://localhost:8000 ;追加 ?demo=1 自动演示第一个示例问题
```

注:8000 被占用时换端口(如 `--port 8001`),开发模式需同步改 `frontend/vite.config.ts`
的 proxy target;演示模式直接访问后端端口。
