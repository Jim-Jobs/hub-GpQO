## 1. 角色与主流程

业务人员只看到问题和回答。分析师可以看到 SQL 和选表理由。数据管理员维护口径和权限。审计人员只读回放记录。

单轮问数流程：

```text
用户问题
  -> F3 结合会话改写成本轮完整问题
  -> F2 取出该用户可见的指标和表
  -> F4 选表，并按外键补齐中间表
  -> F5 生成一条只读 SQL
  -> F6 校验
       通过 -> F8 执行
       失败 -> F7 改写，回到 F6，最多 4 次
  -> F9 用结果写结论
  -> F10 给出图表建议
  -> F13 写入审计
```

多轮时，F3 先把「第二名呢」补成完整问题，再进入同一条链路。外部股票问题走 F15，不进入 SQL 生成。

## 3. 功能说明

### F1 数据库解析

目的：让后续步骤知道有哪些表、字段含义和表之间怎么连。

输入：数据源连接串。Chinook 原型使用同目录 `chinook.db`。

输出：

- 业务表清单。系统表 `sqlite_*` 不进入问数。
- 每个字段的类型、去重数、最小最大、空值个数、最多三个示例。
- 外键列表。
- 每张表一行样例。

规则：解析发生在智能体启动时。表结构变化后需要重新解析，不在每一问里全量重扫。

失败：文件不存在或连接失败时，问数入口直接返回原因，不调用模型。

### F2 指标口径

目的：同一个业务词只对应一种算法。

第一期至少定义：

| 指标 | 定义 | 禁止的算法 |
| --- | --- | --- |
| 曲目销售额 | `SUM(invoice_items.UnitPrice * invoice_items.Quantity)` | 用 `invoices.Total` 代替单曲销售 |
| 客户数 | `COUNT(*)`，按 `customers` 的一行一位客户 | 把发票张数当成客户数 |
| 曲目数 | `COUNT(*)`，按 `tracks` | 把专辑数当成曲目数 |

艺术家销售额的连接固定为 `artists -> albums -> tracks -> invoice_items`。`tracks` 上没有 `ArtistId`。

输入：用户问题中的指标词。输出：指标名、SQL 表达式、必须经过的表。生成和改写提示词只引用这条定义。

失败：问题里的指标没有定义时，先按表字段生成，并在回答里说明口径来自字段而不是指标库。

### F3 问题理解与多轮改写

目的：把依赖上文的短句补成一条可以单独执行的问题。

输入：本轮原话、最近若干轮的问题、最终 SQL 和结果列名。第一期保留最近 10 轮，避免上下文过长。

输出：一条完整中文问题。例如上一轮是「销售额最高的前 5 位艺术家」，本轮「第二名比第一名少多少」应改写为「在曲目销售额前五的艺术家中，第二名的销售额比第一名少多少」。

规则：

- 只补全省略的指标、筛选和排序，不改变用户新提出的条件。
- 改写结果交给 F4，不直接执行上一轮 SQL。
- 单轮完整问题可以不改写。

失败：无法判断追问所指时，向用户确认，不猜测一个指标。

### F4 选表

目的：把全库收成回答本问题需要的表，并补上连接所缺的中间表。

输入：完整问题、表清单、外键、字段示例。

输出：

- 模型或关键词选出的表。
- 补齐路径后的表。例如只选出 `artists` 和 `invoice_items` 时，补上 `albums` 和 `tracks`。
- 一句选表理由。

规则：

- 表名必须来自真实库。
- 模型没有返回有效表名时，按问题中的业务词兜底，如「客户」对应 `customers`，「流派」对应 `genres`。
- 只沿外键补中间表，不把无关子表全部加进来。
- F12 生效后，用户不可见表不进入候选。

失败：兜底后仍然没有表时，告诉用户当前库无法回答，不生成 SQL。

### F5 SQL 生成

目的：根据选中表生成一条 SQLite 查询。

输入：完整问题、选中表的字段和样例、相关外键、F2 的指标定义。

输出：一条 SQL，放在回答的 SQL 代码块中。

规则：

- 只允许 `SELECT` 或 `WITH`。
- 统计问题写 `GROUP BY` 和排序。
- 排行榜的 `LIMIT` 使用问题里的名次。明细查询才使用 `LIMIT 50`。
- `GROUP BY` 的业务字段要出现在 `SELECT` 中，避免只返回一列无名数字。
- 列使用可读别名。

失败：模型没有返回 SQL 时，进入 F7，错误信息为「未生成 SQL」。

### F6 SQL 校验

目的：执行前确认语句安全，并且仍在回答原问题。

输入：SQL、原问题、本轮可用表。

检查顺序：

1. 去掉注释后只能有一条语句。
2. 语句以 `SELECT` 或 `WITH` 开头。
3. 出现 `INSERT`、`UPDATE`、`DELETE`、`DROP`、`ALTER`、`CREATE`、`ATTACH`、`PRAGMA` 则拒绝。
4. 用 `EXPLAIN` 检查表和列是否存在，不返回业务数据。
5. 问题对应的表必须出现在 SQL 中。艺术家销售额必须同时出现 `artists`、`albums`、`tracks`、`invoice_items`。
6. 「多少、数量、销售额、最高、前 N」这类问题必须含聚合函数。
7. 如果所有分组字段都没出现在 `SELECT` 中，判定为未通过。

输出：通过，或一条可交给改写步骤的错误说明。

失败处理：不执行。把数据库错误中的 SQL 正文截掉，只保留原因，避免改写提示被长 SQL 淹没。

### F7 SQL 改写

目的：在校验失败后得到一条仍回答原问题的 SQL。

输入：原问题、失败 SQL、错误原因、本轮可用表的结构。

输出：一条新的 SQL。

规则：

- 最多改写 3 次，加上首次生成共校验 4 次。
- 改写提示中写明必须使用的表和指标公式。
- 若失败原因只是分组字段没有出现在 `SELECT` 中，先用规则把这些字段补进 `SELECT`，不再为此单独请求模型。
- 最后一版仍失败时，向用户返回最后一条错误，不执行半成品。

已验证：`FROM customer` 会因「没有这张表」失败，改写为 `customers` 后通过。

### F8 SQL 执行

目的：在只读连接上取回结果。

输入：通过 F6 的 SQL。

输出：列名和最多 100 行。超过 100 行时标记已截断。

规则：执行前再次做只读检查。用独立连接，查询后回滚，避免失败语句污染后续连接。

失败：数据库在 `EXPLAIN` 之后仍然报错时，把错误交回 F7。次数用尽则停止。

### F9 结果汇总

目的：用中文直接回答问题。

输入：问题、最终 SQL、最多 30 行结果。空结果要明确说没有查到。

输出：一段结论。排名问题先给第一名和关键数字，再保留表格。

规则：

- 结论里的数字必须能在结果中找到。
- 结果列和问题对不上时，说明这张表回答不了问题，不另编一套结论。
- 汇总不重新计算一个结果表里没有的口径。

### F10 可视化

目的：让结果能看，而不是再算一次。

输入：F8 的列类型和行数。

输出：图表类型和用到的列。

| 结果形态 | 图 |
| --- | --- |
| 一个类别列加一个数值列，类别不超过 20 | 条形图 |
| 时间列加数值列 | 折线图 |
| 一行一列数值 | 不画图，只显示数字 |
| 明细很多列 | 表格 |

规则：图的数据就是本次结果的前 30 行。截断时在图下说明。

### F11 会话历史

目的：用户可以换对话，并让追问接上前文。

输入：用户、对话标识、每轮问题、最终 SQL、结果列、结论。

输出：对话列表，以及交给 F3 的最近 10 轮摘要。

规则：切换对话后不携带上一个对话的筛选条件。删除对话时同时保留审计需要的查询记录，见 F13。

### F12 权限与脱敏

目的：模型看不到、SQL 也碰不到用户无权的数据。

输入：用户身份、表权限、列权限、脱敏规则。

输出：过滤后的库结构。电话、邮箱等列在样例和结果中按规则遮盖。

规则：

- 权限在选表之前生效。
- 生成的 SQL 若引用不可见表或列，F6 直接失败，错误信息对用户只说无权访问。
- 第一期可以先实现「登录用户只能访问授权数据源」，行级权限放到数据管理员配置之后。

这是本地 Qwen 指出、当前原型尚未落地的能力。

### F13 审计

目的：一次问答可以回放。

每轮至少记录：时间、用户、对话标识、原始问题、改写后的问题、选中表、每一版 SQL、校验结果、最终行数、模型名、耗时、是否截断。

规则：审计记录不随对话删除而删除。结果明细默认不长期保存全量行，只保存行数和结果哈希；排障需要时可以短期保留前 30 行。

### F14 评测

目的：换模型或改提示词之后，知道问数有没有变差。

固定题至少包括：

| 题 | 期望 |
| --- | --- |
| 每个国家分别有多少位客户？按客户数从高到低排列。 | 第一行 USA，客户数 13；总客户数 59 |
| 曲目数量最多的音乐流派是什么？ | Rock，1297 |
| 销售额最高的前 5 位艺术家是谁？ | 第一名 Iron Maiden，138.60；前五名顺序固定 |
| 错误 SQL：`FROM customer` | 改写后能执行，且按国家给出客户数 |
| `DROP TABLE customers` | 拒绝，数据库不变 |

指标：最终 SQL 执行正确率、平均改写次数、空结果率、回答中的数字是否都能在结果里找到。生成模型和打分过程分开记录。

### F15 外部工具

目的：库里没有的数据，通过工具查询，而不是编进 SQL。

股票行情、新闻走 MCP 工具。工具返回结构化结果后，仍由 F9 汇总，并且说明数字来自工具而不是业务库。

规则：工具失败时返回工具错误，不用库内 SQL 冒充行情。一个问题同时需要库内销售和外部行情时，先分别取数，再汇总，两套数字分开标注来源。

## 4. 界面要点

对话页包含输入框、结论、结果表、SQL、选表理由。SQL 默认折叠，分析师可展开。

失败时显示人能读的原因，例如「没有找到表 customer，已尝试改写」。不把数据库驱动的整段堆栈直接给业务人员。

空结果和无权访问使用不同文案。空结果表示查过了；无权表示没有查询该数据。

## 5. 验收

M1 验收就是 F14 的五道题在 Chinook 上通过，并且任意写操作被拒绝。

M2 再增加：

- 「销售额前五」之后追问「第二名比第一名少多少」，答案为 138.60 与 105.93 的差。
- 回答同时给出结论和 SQL。
- 类别加数值的结果能对应到条形图数据，图中数字与表一致。

M3 再增加：去掉某用户对 `customers` 的权限后，客户数问题被拒绝，审计里仍能看到这次拒绝。
