本文说明项目要解决什么问题、必须具备哪些能力、做到哪一步算成功。功能细节见《功能设计文档》，模块和接口见《技术设计文档》。

## 1. 背景

现有 BI 能出报表，但业务人员要先懂表结构、筛选器和公式。临时问题，例如「每个国家有多少客户」「哪个流派曲目最多」「哪几位艺术家销售额最高」，不值得为每个问题做一张报表。

课程里已经有两条线：

- Chinook 上的 SQL Agent：数据库解析、选表、生成 SQL、校验、改写、执行、汇总。
- 股票 ChatBI：用云端 MCP 查股票、分析股票，并保留多轮对话。

本项目把这两条线收成一个数据智能体：业务人员用中文提问，系统在权限范围内查询，返回可核对的数字、SQL 和说明。

## 2. 模型沟通记录

用同一份问题分别联系 ChatGPT、DeepSeek、通义千问和豆包，问题是：业务人员用自然语言问数时，数据智能体必须具备哪些产品能力、功能模块和技术底线，以及最容易被忽略的三点。约束是用户不会写 SQL、数字必须来自查询、要能出图和多轮追问。

| 对象 | 接入方式 | 结果 |
| --- | --- | --- |
| ChatGPT | 环境中没有可用的 OpenAI 密钥 | 未接通 |
| DeepSeek | `https://api.deepseek.com`，课程材料中的密钥 | 401，密钥无效 |
| 通义千问云端 | 百炼兼容接口，课程材料中的密钥 | 401，密钥无效 |
| 通义千问本地 | Ollama `qwen3:0.6b` | 已回复 |
| 豆包 | 环境中没有火山引擎密钥 | 未接通 |

本地 Qwen 的原文如下：

> 1. 产品能力：支持数据清洗、分析、可视化、多轮追问，响应时间≤3秒
> 2. 功能能力：实现自然语言处理（NLP）、数据清洗、分析算法、可视化工具、多轮追问处理
> 3. 技术能力：架构可扩展性、权限细粒度、审计实时性、评估透明性
> 最容易被忽略的 3 个能力：
> - 数据加密与访问控制
> - 实时性处理与异常检测
> - 多语言支持与跨文化适配

这是 0.6B 模型的回答，条目粗，不能代表通义千问旗舰模型，更不能写成另外三家已经发表的意见。下面的能力设计以这次回复为输入，再按企业问数场景补全。未接通的模型不引用虚假观点。

对这条回复的取舍：

- 采纳：可视化、多轮追问、细粒度权限、审计、评估要透明、访问控制不能漏。
- 收窄：数据清洗留在入库前，问数智能体消费已经建模的表和指标，不在对话里做 ETL。
- 调整时限：简单查询可以追求数秒内返回；带校验和改写的复杂连接，在本地小模型上做不到稳定 3 秒。时限按查询复杂度分级。
- 后置：多语言不是第一期范围，第一期中文问数。

四家模型在架构上作为可替换的生成器，不绑死某一家。密钥恢复后，SQL 生成、改写、汇总和评测裁判可以分派到不同模型，裁判与生成分开，避免模型给自己的 SQL 打分。

## 3. 目标

业务人员用自然语言提出统计、排名、对比和明细问题，系统完成：

1. 理解问题并选对表。
2. 生成只读 SQL，执行失败或答非所问时改写。
3. 只根据查询结果用中文说明，并保留 SQL 供核对。
4. 多轮追问能接上一次的口径、筛选和排序。
5. 越权、写库和多语句请求被拒绝，并留下审计记录。

### 3.1 成功标准

| 标准 | 判定 |
| --- | --- |
| 问数正确 | 标准题的数字与数据库直接查询一致 |
| 不编造 | 回答中的每个数字都能在结果表中找到 |
| 可解释 | 每次回答附带最终 SQL、选中的表和校验记录 |
| 可恢复 | 错误表名、歧义列名能在有限次数内改写或明确失败 |
| 可审计 | 能按用户、时间和 SQL 回放一次问答 |
| 可替换模型 | 更换 OpenAI 兼容接口后，主流程不改 |

Chinook 上已经核对过的基线：

- 各国客户数：USA 13、Canada 8、France 5、Brazil 5、Germany 4。
- 曲目最多的流派：Rock，1297。
- 销售额前五：Iron Maiden 138.60、U2 105.93、Metallica 90.09、Led Zeppelin 86.13、Lost 81.59。
- 表名写成 `customer` 时，校验失败并改写到 `customers`。
- `DROP`、`INSERT` 等语句直接拒绝。

### 3.2 不做的事

- 不把智能体做成通用聊天机器人。
- 第一期不执行写入、更新、删除和建表。
- 不在对话中清洗原始数据或训练预测模型。
- 不承诺替代固定报表的排版、订阅和权限审批流。

## 4. 用户与场景

| 角色 | 要完成的事 |
| --- | --- |
| 业务人员 | 用中文问指标、排名、对比，看结果和简短结论 |
| 分析师 | 查看 SQL 和选表理由，把问句沉淀成指标 |
| 数据管理员 | 维护表关系、指标口径、脱敏和数据源 |
| 审计人员 | 回放谁在什么时间问了什么、执行了哪条 SQL |

典型场景：

- 单表统计：每个国家有多少客户。
- 跨表排名：艺术家销售额前五，必须经过专辑和曲目，不能把订单总额当成曲目销售额。
- 错误恢复：模型写出不存在的表或列，系统改写后再执行。
- 多轮：先问销售额前五，再问「第二名比第一名少多少」。
- 外部数据：股票行情走 MCP 工具，库内经营数据走 SQL，两类结果可以在同一轮对话里一起解释。

## 5. 能力地图

```text
问数入口
  -> 会话与问题改写
  -> 权限过滤后的库结构 / 指标口径
  -> 选表并补齐连接路径
  -> SQL 生成
  -> 校验（只读、语法、是否回答原问题）
  -> 改写（有限次数）
  -> 执行与截断
  -> 汇总、图表、SQL 回显
  -> 审计与评测
```

必须具备的能力分成三层。

产品能力：

- 中文问数，用户不写 SQL。
- 统计、排名、对比、明细四类问题都能回到一张结果表。
- 结论、结果表、SQL 同时给出。
- 多轮追问继承上一轮的指标、时间和筛选。
- 图表只表达本次结果，不另算一套数。
- 没有权限的表和列不会进入提示词，也不会出现在 SQL 里。

功能能力：

- 数据库解析：表、字段、主外键、样例值和空值情况。
- 选表：模型选择加关键词兜底，再按外键补上中间表。
- SQL 生成、校验、改写、执行、汇总。这七步是当前原型的主链路。
- 指标口径：销售额等指标有唯一定义，避免同一问题多种算法。
- 会话、可视化、审计、离线评测。

技术能力：

- 模型适配层使用 OpenAI 兼容接口，可指向 DeepSeek、百炼 Qwen、豆包或本地 Ollama。
- 数据库账号只读，应用层再拒绝多语句和写操作。
- 每次问答记录问题、选表、每一版 SQL、报错、行数和模型名。
- 评测集固定，换模型后可以比较正确率和改写次数。
- 传输和库连接使用加密通道；敏感列默认可配置脱敏。

## 6. 里程碑

| 阶段 | 交付 | 状态 |
| --- | --- | --- |
| M1 单库只读问数 | Chinook 七步工作流，标准题数字正确 | 原型已跑通 |
| M2 会话与展示 | 多轮追问、结果表、SQL 回显、基础图表 | 待做 |
| M3 口径与权限 | 指标定义、列级权限、脱敏、审计回放 | 待做 |
| M4 外部工具 | 股票 MCP 与库内问数放在同一对话里 | 股票助手已有独立原型 |

M1 的实现入口是 `sql_agent.py` 的 `SQLAgent.run()`。M2 之后把这一调用放到 FastAPI 会话服务后面，前端沿用股票助手里已经规划的对话列表。

## 7. 风险

| 风险 | 表现 | 处理 |
| --- | --- | --- |
| 模型答非所问 | SQL 能执行，但统计的不是用户问的指标 | 校验「问题相关的表」和聚合函数，失败则改写 |
| 小模型不稳定 | 漏掉分组字段，或反复返回同一条 SQL | 规则补全分组字段；限制改写次数并明确失败 |
| 口径分裂 | 销售额有人用订单总额，有人用明细单价乘数量 | 指标层写死算法，提示词只引用该定义 |
| 密钥不可用 | 云端 401，本地小模型能力不足 | 适配层可切换；评测不通过则不允许换到该模型 |
| 结果被截断后胡编 | 汇总模型补出结果里没有的数字 | 汇总提示禁止编造；抽查回答中的数字是否来自结果表 |
| 实时数据不一致 | 问数过程中库被写入，前后数字对不上 | 第一期面向相对稳定的分析库；回答带上查询时间 |
