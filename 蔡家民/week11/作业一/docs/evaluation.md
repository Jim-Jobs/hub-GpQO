# 评测说明与人工审核清单

## 当前题集

120道题：112道可查询、4道需澄清、4道不支持。开发/验证/测试切分为20/40/60。79个查询模板族中的参数变体保持同一切分。作者侧已审阅模板口径、执行参考SQL、保存快照、核对必要表，并用11项独立Python聚合交叉验证关键统计；这不是独立第三方人工认证。

每题记录问题、日期锚点、预期状态、必要表、SQL/参数、顺序策略、数据库指纹、标准意图和审阅状态。参数化查询模板经过分组；不同模板仍可能共享相似业务知识，不能宣称完全没有语义近似性。

## 结果比较

同一个数据库执行参考SQL和待测SQL。数值允许1e-6绝对/相对误差；有顺序要求严格按序；无顺序要求进行保留重复次数的一对一匹配。NULL与0、文本数字与数值不同。展示被截断的结果不判为正确。

执行同结果不证明两个SQL在所有数据上等价；需要人工口径检查和后续反例小库。别名可不同，但列语义顺序必须相同。对于多个合理输出列方案，应人工审核并扩展比较策略。

## 错误分析

报告中的first_detected_failure仅用于查找trace。检查选表、连接粒度、日期过滤、排名与SQL参数，然后再判断根因。不能把执行器报告错误直接归因于执行器能力差。

建议手动复盘表：case_id、预期口径、实际输出、最早错误、证据、修改方案、验证结果。正式成绩应包含所有题和失败项，不能只截图成功案例。

## 校验器测试

当前unittest覆盖编译错误、聚合粒度、时间缺失、选择范围、禁止操作、注入参数、结果截断、计算中断、空结果/NULL/0、修复、重试终止、比较器及120题回放路径。另有独立30项专项和3组反例检查。不是所有这些都属于模型能力测试。

专项包含24个已标注错误和6个正确对照；其中16个可修复错误用显式修复fixture检验编排。这个16/16是脚本修复回放成功数，不是模型自动修复率。反例数据库独立于原库，证明一些错误SQL即使能执行也会返回不同结果。

## 分阶段与替换诊断

stages在标准意图下评选表、标准表结构下评SQL、标准查询结果下评文本；没有裁判时只保存文本，不给虚构分数。diagnose-case分别不替换、替换意图、替换意图及选表、替换至SQL；各次运行重新创建模型状态。

替换诊断记录采用专门的协议标识，不能混作普通端到端结果。检测错误的位置和根因不同；恢复是证据，不证明根因唯一。

## 参考答案审阅方法

1. 逐题确认自然语言问题与参考SQL含义一致。
2. 检查JOIN、聚合、时间起止、排序并列和NULL。
3. 必要时手工用第二条SQL交叉验证。
4. 审核同义改写/相同查询模板是否跨切分泄漏。
5. 作者侧完成后更新review_status及题集版本，冻结测试集；不要冒充独立人工认证。
6. 用开发集试运行真实模型，确认格式和用量；验证集用于迭代；测试集最后运行。

## 大模型裁判

可选独立服务对回答忠实度、覆盖、限制说明评分。错误数字不能被流畅语言抵消。抽样20个回答做人工-模型对照。没有运行裁判时，报告不提供任何虚构的文本质量分。
