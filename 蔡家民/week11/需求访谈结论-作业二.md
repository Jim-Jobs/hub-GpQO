# 需求访谈结论：项目一 · Debug 研发知识助手

- 整理日期：2026-10-22
- 状态：待用户确认
- 阶段：需求访谈结论，尚未进入技术设计或开发
- 确认流程：用户确认本结论 → 输出《技术方案》 → 用户确认技术方案 → 开始开发

## 1. 项目目标

建设一个围绕 **Debug 功能理解、维护与扩展的研发知识助手**，作为面向 2027 年春季社招的第一个个人 RAG 项目。

首版交付包括可独立运行的演示、经过核对的知识资料，以及可复现的离线评估。不以公司上线、真实用户规模或线上业务收益作为完成前提。

## 2. 已确认决定

| 事项 | 已确认内容 |
|---|---|
| 首要用户 | 研发维护者、新接手项目的开发者 |
| 知识范围 | Debug 专题，以及理解和扩展 Debug 必需的公共机制 |
| 业务重点 | 复用已有数据或控制链路，理解、维护和扩展展示项与操作入口 |
| 代表场景 | 相机状态展示、悬浮窗、文件导出；第一条验收样例待资料整理后选择 |
| 版本范围 | 一个明确的当前实现快照，注明适用版本、更新时间和功能状态 |
| 产品输入 | Markdown、纯文本形式的已整理、核对文档，以及用户问题 |
| 回答输出 | 前置条件、操作步骤、模块职责、注意事项、验证清单和来源；按问题需要组织 |
| 连续问答 | 支持当前会话的必要追问和上下文继承 |
| 知识维护 | 由用户统一核对、维护，手动发起新增、替换、删除和更新 |
| 演示方式 | 在用户自己的电脑运行、现场操作或共享屏幕 |
| 外部服务 | 允许调用外部模型服务，具体服务及费用待确认 |
| 推进节奏 | 按阶段产物推进，暂不设固定工期和每周投入要求 |

## 3. 核心流程

### 3.1 资料维护

整理资料 → 标明来源、适用版本和功能状态 → 核对内容 → 手动更新知识库 → 查看更新结果 → 验证新内容生效、旧内容不再被误用。

### 3.2 用户问答

提出问题 → 必要时澄清条件 → 根据文档提供指导与来源 → 用户继续追问 → 在当前会话内继承相关条件。

资料不足、版本不匹配或超出覆盖范围时，明确说明限制，不把推测写成已核实的业务事实。

## 4. MVP 范围

- 一套围绕 Debug 专题的文档知识库。
- 有来源依据的研发问答，包括必要的跨章节信息整合。
- 当前会话内的追问和连续问答。
- 来源文档、章节及适用版本的展示。
- 区分已交付、开发中和未来设想。
- 手动维护文档，并检查更新结果。
- 本机演示和可复现的对照评估。

## 5. 明确不做的事项

- 首版不覆盖整个 App，也不扩展其他独立专题。
- 不直接检索源码、分析运行日志或 Debug 导出包。
- 不执行设备控制、文件导出等真实业务操作；这些是知识讲解的对象。
- 不生成新的完整实现代码；可引用文档已有示例。
- 不支持历史版本比较、长期记忆。
- 不做多人协同维护、个人知识库隔离、公开访问服务。
- 不要求 PDF、Word、扫描件或 OCR。
- 标准化代码生成、质量检测及其他知识库扩展列为后续候选方向。

## 6. 数据、权限与成本约束

- **两条资料线并行：**先编写通用演示资料，同时确认公司业务资料的可用范围；分别标明来源。
- 模拟内容必须明确标注，不能描述成公司实际实现。
- 公司资料尚未确认可用；脱敏不自动等于获得使用许可。
- 公司资料的个人使用范围与外部发送范围分别确认。
- 预算暂未确定。技术方案阶段先估算开发、评测和演示费用，用户确认后再启动付费任务。
- 模型、框架、数据库、检索与文档处理策略均未确定。老师的建议属于候选方法，后续根据实际问题和对照结果取舍。

## 7. 验收标准

首版需提供以下可检查的证据：

| 验收项 | 检查内容 |
|---|---|
| 业务指导 | 代表场景的回答与核对后的资料一致，关键步骤、约束和验证方式完整 |
| 来源依据 | 引用能够定位，且实际支持对应结论；适用版本与功能状态表达正确 |
| 追问与连续问答 | 缺少条件时能澄清，后续问答正确继承条件，避免混淆展示位置或任务 |
| 能力边界 | 对资料不足、版本不匹配和范围外问题明确说明限制 |
| 资料更新 | 新增、替换、删除成功后，后续问答使用正确内容；失败时能识别更新未成功 |
| 对照评估 | 比较普通搜索、完整文档直接问答与 RAG，记录优势、失败案例和局限 |
| 可复现性 | 固定资料与评测版本，人工核对问题、参考答案和证据，区分调试集与最终评估集 |

评估覆盖检索命中、答案正确性与完整性、引用、拒答、连续问答、耗时和成本。**具体题量、数值门槛和测量条件尚未确认**，需结合资料审查与初步实验确定，并在最终验收前固定。

离线结果只用于说明对应测试条件下的表现，不写成线上业务收益。
