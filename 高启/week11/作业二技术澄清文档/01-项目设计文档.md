## 1. 项目概述

### 1.1 项目背景

传统股票行情平台主要采用菜单、筛选器、图表和指标配置方式提供金融数据分析能力。用户需要熟悉股票代码、指标定义和相关操作流程，才能完成较为复杂的分析。

随着大语言模型和 Agent 技术的发展，可以通过自然语言交互降低股票数据查询与分析的使用门槛。

本项目计划构建一套面向中国 A 股市场的 ChatBI 智能分析平台，结合行情数据服务、技术指标计算、财务分析、可视化和 AI Agent，实现通过自然语言完成股票信息查询、行情分析及股票对比等任务。

例如，用户可以输入：

- 查询贵州茅台最近一年的股价走势。
- 分析宁德时代近期的 MACD 和 RSI 指标。
- 对比贵州茅台与五粮液近半年的价格表现。
- 查找最近一个交易日成交量明显放大的股票。
- 分析某只股票最近几个报告期的净利润和 ROE 变化。

系统负责识别用户意图、调用对应业务工具、获取真实数据、计算指标，并生成结构化分析结果及交互图表。

### 1.2 项目定位

项目定位为：

基于 AI Agent 的中国 A 股智能查询与数据分析平台。

产品面向公众，长期具备商业化运营能力。

平台不是单纯的聊天机器人，也不是传统股票行情看盘工具，而是把自然语言查询、金融数据分析和数据可视化整合在统一界面中的 ChatBI 应用。

核心设计原则：

1. 自然语言驱动业务查询与分析。
2. 所有行情和指标结果基于真实数据或确定性计算。
3. AI 负责理解、规划、工具编排及分析解释。
4. 金融计算由可验证的 Python 业务模块完成。
5. 分析结论必须能够追溯数据来源及计算口径。
6. 系统允许持续增加数据源、模型和分析工具。
7. 第一阶段优先完成可运行、可演示的核心 MVP。

### 1.3 产品目标

业务目标

建立可供公众使用的 A 股智能查询与分析平台，逐步形成会员、积分及商业运营能力。

用户目标

降低股票数据获取、技术指标分析和股票比较的操作门槛，让用户通过自然语言获取结构化分析结果。

技术目标

建立可扩展的 Python 技术架构，支持行情缓存、多数据源适配、AI 工具编排、交互式可视化、任务管理和分阶段功能扩展。

MVP 目标

完成从用户自然语言提问，到行情获取、指标计算、Agent 工具调用、结构化回答及图表展示的完整业务闭环。

## 2. 目标用户与角色

### 2.1 目标用户群体

| 用户群体       | 典型需求                               |
| -------------- | -------------------------------------- |
| 普通股票投资者 | 查询股价、查看走势、理解技术指标       |
| 股票分析爱好者 | 技术指标组合分析、股票对比             |
| 进阶分析用户   | 条件选股、财务分析、多指标研究         |
| 付费会员       | 使用更高额度或更多高级分析能力         |
| 系统管理员     | 用户管理、模型配置、积分管理、数据监控 |

### 2.2 角色体系

长期采用四级角色：

| 角色     | 权限范围                                   |
| -------- | ------------------------------------------ |
| 游客     | 有限的股票查询与 AI 试用                   |
| 免费用户 | 基础查询、有限分析额度及个人数据保存       |
| 付费用户 | 根据会员套餐获得扩展使用额度和功能         |
| 管理员   | 用户、权限、积分、模型、工具和系统运营管理 |

第一阶段 MVP 不要求立即实现完整角色和登录系统。

完整账号体系属于后续开发阶段，但应在架构设计中预留扩展空间。

## 3. 产品业务范围

### 3.1 股票市场范围

只覆盖中国 A 股市场。

第一版不要求提供：

- 港股及美股行情。
- 外汇、期货、数字货币交易。
- 实时逐笔成交数据。
- Level-2 深度行情。
- 自动股票交易或证券账户下单。

### 3.2 行情数据范围

支持以下数据：

- 股票代码及名称。
- 股票基本信息。
- 历史开高低收价格。
- 成交量与成交额。
- 日线、周线和月线。
- 前复权、后复权、不复权。
- 历史价格走势图。
- 常用技术指标。

分钟线不纳入内部行情存储及计算范围。

对于分钟级行情需求，提供第三方行情平台的外部链接，由用户自行跳转查看。

### 3.3 AI 分析范围

支持自然语言查询及多步骤分析。

长期能力包括：

- 股票信息查询。
- 行情分析。
- 技术指标分析。
- 股票对比分析。
- 基础股票筛选。
- 财务与估值分析。
- 多工具组合查询。
- 结构化证据和风险提示。

AI 不负责自行生成未经验证的股价、财务数字或技术指标数值。

## 4. 分阶段建设规划

项目明确采用分阶段开发策略，而不是一次性完成所有功能。

### 4.1 第一阶段：核心 MVP

目标：建立完整的股票 ChatBI 分析闭环。

主要功能：

1. 股票代码及名称搜索。
2. 股票基本信息查询。
3. 历史行情获取。
4. SQLite 按需缓存与补齐。
5. 日线、周线、月线展示。
6. 三种复权方式切换。
7. 交互式 K 线图。
8. 常用技术指标。
9. DeepSeek 云端模型接入。
10. LangGraph Agent 多工具调用。
11. AI 流式分析结果。
12. 数据来源、日期及分析局限展示。
13. 基础异常处理。
14. 原生 Python 本地运行与演示。

第一阶段只接入 DeepSeek 作为 AI 模型，优先使用 AKShare 获取股票数据。

### 4.2 第二阶段：分析能力增强

在 MVP 基础上逐步加入：

- 更完整的股票比较分析。
- 全市场基础条件选股。
- 财务指标分析。
- PE、PB、市值等估值分析。
- 更丰富的技术指标。
- 高级 Agent 工具组合。
- 完善的分析结果卡片。
- 扩展行情数据源。
- 增强数据质量保障。

财务分析覆盖：

- 营业收入。
- 净利润。
- ROE。
- 毛利率。
- 资产负债率。
- 市盈率 PE。
- 市净率 PB。
- 总市值及相关趋势。

### 4.3 第三阶段：用户与商业功能

建设完整用户体系与商业运营能力，包括：

- 手机号验证码登录。
- 邮箱密码登录。
- 微信等第三方登录。
- 游客试用。
- 完整聊天历史。
- 会话重命名与删除。
- 自选股及分组。
- 会员套餐。
- 积分账户。
- Token 和工具调用计费。
- 充值及积分流水。
- 管理员运营后台。

第一版商业功能不要求真实支付。

系统需要预留微信支付、支付宝等支付接口。

### 4.4 第四阶段：稳定性与上线准备

包括：

- 全 A 股交易日行情同步。
- 多数据源质量校验。
- 主备数据源切换。
- 任务重试与异常恢复。
- 完整审计日志。
- 系统监控。
- 权限与安全加固。
- 性能优化。
- 数据授权核验。
- 商业上线合规检查。

以上为建议实施顺序。为保证 MVP 运行所需的基础能力，可以将少量后续阶段的底层机制提前实现，但不因此扩大第一阶段的业务验收范围。

## 5. MVP 验收标准

第五十轮最终确认的十项验收内容如下。

| 编号  | 验收项目       | 验收要求                                   |
| ----- | -------------- | ------------------------------------------ |
| AC-01 | 股票查询       | 输入股票代码或名称，能够查询股票基本信息   |
| AC-02 | 历史行情缓存   | 获取历史行情，并按需缓存到 SQLite          |
| AC-03 | K 线周期与复权 | 支持日线、周线、月线，以及三种复权方式     |
| AC-04 | 交互式图表     | 支持交互 K 线、技术指标和图表操作          |
| AC-05 | 技术指标       | 支持 MA、MACD、RSI、KDJ、BOLL 等常用指标   |
| AC-06 | 自然语言分析   | DeepSeek 能够理解并处理股票分析问题        |
| AC-07 | 多工具组合     | LangGraph 能够根据问题组合调用多个业务工具 |
| AC-08 | 分析可追溯     | AI 回答标注数据来源、日期及分析局限        |
| AC-09 | 异常处理       | 行情或模型接口异常时提供合理错误提示       |
| AC-10 | 本地运行       | 可在本地 Python 环境启动并完整演示         |

验收判定原则：

- 以上十项必须全部通过。
- 指标数值必须能够通过 Python 计算结果核验。
- AI 不得使用虚构行情代替失败的数据请求。
- 复权、周期和数据日期必须与分析结果一致。
- 主要业务接口具备自动化测试。
- 本地部署提供可重复执行的启动说明。

## 6. 主要技术选型

| 技术领域     | 已确认方案      | 说明                     |
| ------------ | --------------- | ------------------------ |
| 开发语言     | Python          | 核心开发语言             |
| 前端框架     | Streamlit       | 股票界面和 AI 对话       |
| 后端框架     | FastAPI         | REST API、SSE、业务服务  |
| Agent 框架   | LangGraph       | 工作流、状态及工具执行   |
| MVP 大模型   | DeepSeek        | 第一阶段只接入一个云模型 |
| 后续模型策略 | 云端与本地混合  | 多模型适配和用户配置     |
| MVP 数据源   | AKShare         | A 股行情及基础股票数据   |
| 数据源架构   | 统一适配层      | 后续支持多个数据供应方   |
| 数据库       | SQLite          | 第一版业务和行情存储     |
| 图表组件     | 优先考虑 Plotly | 最终以功能验证为准       |
| 调度系统     | APScheduler     | 后续定时任务调度         |
| 任务执行     | 独立 Worker     | 避免后台任务阻塞 API     |
| 部署方案     | 原生 Python     | 虚拟环境、依赖和启动脚本 |
| 实时输出     | SSE             | AI 和任务进度事件        |

### 6.1 技术选型原则

- 优先选择易于本地开发和调试的方案。
- 不为第一版引入不必要的分布式组件。
- 核心业务模块与具体数据源和模型解耦。
- 数据存储和外部依赖支持未来替换。
- 外部接口异常不能导致整个系统不可用。
- 保留向 PostgreSQL、Redis 和任务队列迁移的空间。

## 7. 主要非功能性要求

### 7.1 可维护性

业务逻辑应分层组织，避免把所有操作写在 Streamlit 页面或 Agent 提示词中。

### 7.2 可扩展性

未来能够新增：

- 股票分析工具。
- 行情数据源。
- AI 模型。
- 技术指标。
- 会员及积分规则。
- 管理后台模块。

### 7.3 数据可靠性

缓存数据必须保存日期、来源、周期、复权口径或复权因子版本等必要信息。

应能识别缺失、重复、不合法及过期数据。

### 7.4 可观测性

需要具备：

- API 日志。
- 数据源异常日志。
- Agent 工具执行日志。
- 请求标识和任务标识。
- 错误分类。
- 基础运行健康检查。

### 7.5 安全性

长期要求包括：

- 身份认证。
- 用户权限隔离。
- API 密钥安全保存。
- 敏感配置不写入代码仓库。
- 积分扣减审计。
- 管理员操作审计。

MVP 至少必须确保 DeepSeek API Key 不暴露到前端。

## 8. 项目风险

| 风险                 | 影响               | 应对策略                       |
| -------------------- | ------------------ | ------------------------------ |
| AKShare 上游接口变化 | 行情查询失败       | 适配层隔离、错误处理、接口测试 |
| 行情数据不完整       | 指标计算不准确     | 数据校验、明确缺失、禁止伪造   |
| 复权口径不一致       | 图表与指标结果冲突 | 统一复权参数和计算流程         |
| DeepSeek API 不可用  | AI 功能不可用      | 超时、重试、用户提示           |
| Agent 调用错误工具   | 分析失败或成本增加 | 工具 Schema、调用限制、日志    |
| SQLite 并发写入      | 数据库锁冲突       | WAL、短事务、写入协调          |
| 第三方接口限流       | 数据同步延迟       | 缓存、重试、速率控制           |
| AI 不确定性          | 用户误解分析结论   | 事实与推断分离、风险提示       |
| 商业数据授权         | 正式上线受限       | 上线前完成授权核验             |
| 金融服务合规         | 商业化范围受约束   | 上线前审查适用监管要求         |

### 8.1 数据商业授权策略

第四十三轮已确认选择：

开发阶段优先，正式上线前集中审查商业授权。

实施时仍须遵守数据接口及底层数据的现有条款。

在未获得必要授权的情况下，不应把相关数据直接用于未经许可的商业展示或再分发。
