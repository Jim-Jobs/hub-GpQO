## 1.2 产品简介

股票查询 ChatBI 是一款以自然语言交互为核心的中国 A 股智能查询与数据分析平台。

用户可以像使用聊天助手一样，直接提出股票相关问题，例如：

- 查询贵州茅台最近一年的历史行情。
- 查看宁德时代的日 K 线和 MACD 指标。
- 分析五粮液最近三个月的价格走势。
- 对比贵州茅台和五粮液近半年的市场表现。
- 筛选最近一个交易日成交量放大的股票。
- 查看某家公司最近几个报告期的盈利变化。

系统通过 AI Agent 理解用户问题，调用股票信息、行情、技术指标、股票比较或财务分析等业务工具，最终形成结构化分析结果及交互图表。

## 1.3 核心设计原则

### 1.3.1 自然语言驱动

用户不需要熟悉复杂菜单，也可以通过自然语言完成股票查询和分析。

### 1.3.2 数据驱动分析

行情价格、技术指标和财务数字必须来自真实数据或确定性业务计算，不能由大语言模型自行编造。

### 1.3.3 可解释、可追溯

分析结果应说明：

- 数据来源。
- 数据截至日期。
- 股票标识。
- K 线周期。
- 复权类型。
- 技术指标及参数。
- 计算依据。
- 数据缺失或分析局限。

### 1.3.4 工具化业务能力

AI Agent 负责问题理解、任务规划和工具组合，具体股票查询、指标计算等操作由固定业务接口完成。

### 1.3.5 分阶段交付

第一阶段优先形成完整的股票分析业务闭环，用户体系、商业化功能和复杂运营能力在后续阶段开发。

# 2. 产品范围

## 2.1 市场范围

本产品仅面向中国 A 股市场。

支持沪市、深市、北交所等 A 股股票，实际股票列表以所接入数据源的覆盖范围为准。

第一阶段不要求提供：

- 港股和美股行情。
- 期货及外汇行情。
- 数字货币行情。
- 股票交易和自动下单。
- 券商账户接入。
- 实时逐笔成交。
- Level-2 行情。

## 2.2 行情范围

第一阶段支持：

- 股票基础信息。
- 日线行情。
- 周线行情。
- 月线行情。
- 历史成交量。
- 历史成交额。
- 前复权。
- 后复权。
- 不复权。
- 常见技术指标。

不在系统内部提供分钟 K 线分析。

当用户需要查看分钟线时，系统可提供经验证的第三方行情网站链接。

## 2.3 产品功能边界

本产品定位为股票信息查询与数据分析工具，不提供自动交易执行。

AI 输出用于辅助用户理解股票数据，不保证市场预测的准确性。

针对具有不确定性的分析结论，应明确区分事实、推断与假设，并展示风险提示。

# 3. 用户角色设计

## 3.1 用户角色

长期支持四种用户角色。

| 角色     | 描述               | 主要能力                         |
| -------- | ------------------ | -------------------------------- |
| 游客     | 未登录用户         | 有限的查询及 AI 试用             |
| 免费用户 | 已注册普通用户     | 基础查询、分析及历史记录         |
| 付费用户 | 购买会员权益的用户 | 更高额度或更多高级能力           |
| 管理员   | 平台运营管理人员   | 用户、数据、模型、工具和运营管理 |

## 3.2 权限原则

系统采用角色与功能权限相结合的方式控制访问。

主要权限包括：

- 股票查询权限。
- AI 分析权限。
- 工具调用权限。
- 查询次数限制。
- Token 使用额度。
- 聊天记录保存权限。
- 自选股管理权限。
- 管理后台访问权限。

具体额度和套餐数值属于运营配置，不在本版本固定。

## 3.3 MVP 用户模式

第一阶段暂不要求完整实现注册、登录和会员系统。

MVP 可以使用本地单用户演示模式完成股票查询与 AI 分析功能验收。

后续加入身份认证时，应保持股票查询和分析接口的业务行为不变。

# 5. 股票搜索功能设计

## 5.1 功能编号

```
F01-股票搜索
```

## 5.2 功能描述

用户可以通过股票代码、股票名称或名称关键字查询 A 股股票。

示例：

```
600519
贵州茅台
茅台
000858
五粮液
```

## 5.3 输入参数

| 参数    | 类型    | 必填 | 说明           |
| ------- | ------- | ---- | -------------- |
| keyword | String  | 是   | 股票代码或名称 |
| limit   | Integer | 否   | 最大返回条数   |

## 5.4 输出结果

每条匹配结果包括：

- 股票代码。
- 股票名称。
- 交易所。
- 股票状态（数据源支持时）。
- 统一股票标识。

## 5.5 业务流程

```
用户输入关键词
      ↓
检查输入是否合法
      ↓
判断股票代码或名称
      ↓
查询本地股票基础信息
      ↓
必要时更新数据源
      ↓
生成候选结果
      ↓
用户选择目标股票
      ↓
进入股票详情或分析
```

## 5.6 业务规则

1. 用户可输入纯数字代码或股票名称。
2. 股票代码在系统内部采用统一标识格式。
3. 对名称模糊搜索返回候选股票列表。
4. 当存在多个候选股票时，不应随意选择其中一只。
5. 查询股票基本资料时，应优先使用本地有效缓存。
6. 股票基础资料应具有可更新机制。
7. 已退市股票的历史数据不应被无条件删除。

## 5.7 异常处理

| 场景             | 系统处理                         |
| ---------------- | -------------------------------- |
| 输入为空         | 提示输入股票代码或名称           |
| 代码不存在       | 提示未找到对应股票               |
| 名称存在多个候选 | 返回候选列表                     |
| 数据源不可用     | 根据有效缓存情况返回结果或错误   |
| 返回数据格式异常 | 记录异常，不展示未验证的股票信息 |

## 5.8 验收标准

输入 `600519` 和“贵州茅台”，系统能够识别为同一只股票，并展示一致的股票标识和基础信息。

# 7. 历史行情查询功能设计

```

```

## 7.2 功能描述

## 7.3 支持周期

| 周期      | 是否支持 | 说明         |
| --------- | -------- | ------------ |
| 日线      | 是       | 按交易日展示 |

| 月线      | 是       | 按交易月展示 |

| 15 分钟线 | 否       | 外部平台链接 |
| 30 分钟线 | 否       | 外部平台链接 |

## 7.4 输入参数

| 参数       | 类型   | 说明                   |
| ---------- | ------ | ---------------------- |
| symbol     | String | 股票代码               |
| start_date | Date   | 查询开始日期           |
| end_date   | Date   | 查询结束日期           |
| period     | Enum   | daily、weekly、monthly |
| adjust     | Enum   | none、qfq、hfq         |

## 7.5 输出字段

| 字段       | 含义         |
| ---------- | ------------ |
| date       | K 线日期     |
| open       | 开盘价       |
| high       | 最高价       |
| low        | 最低价       |
| close      | 收盘价       |
| volume     | 成交量       |
| amount     | 成交额       |
| period     | 行情周期     |
| adjust     | 复权方式     |
| source     | 数据来源     |
| updated_at | 数据更新时间 |

金额单位、成交量单位等需要在适配层统一，并在响应元数据中明确标注。

## 7.6 查询流程

```
用户选择股票与行情条件
          ↓
校验股票和日期参数
          ↓
查询 SQLite 缓存
          ↓
检查所需交易区间的数据覆盖
          ↓
      是否需要补齐？
       /          \
     否            是
     ↓             ↓
读取缓存       调用 AKShare
     │             ↓
     │          解析数据
     │             ↓
     │          数据校验
     │             ↓
     │          写入缓存
     └──────┬──────┘
            ↓
     生成周期行情
            ↓
      返回结果和元数据
```

## 7.7 业务规则

1. 默认使用最近一个可用交易日作为数据截止日期。
2. 允许用户指定历史查询范围。
3. 不将周末、法定休市日直接视为数据缺失。
4. 停牌不等同于数据源遗漏。
5. 需要区分原始行情和复权后的行情。
6. 发生数据源错误时不得生成虚假价格。
7. 数据过期或使用旧缓存时，应向调用方提供对应状态。
8. 查询结果必须包含来源和实际覆盖区间。

# 8. 行情缓存管理功能设计

## 8.1 功能编号

```
F04-行情缓存管理
```

## 8.2 功能目标

减少外部接口重复请求，提高历史行情查询性能，并为技术指标计算提供一致的数据基础。

## 8.3 已确认缓存策略

**按需获取并缓存至 SQLite，用户查询时检查并补齐。**

## 8.4 缓存功能

- 股票基本信息缓存。
- 原始日线行情缓存。
- 数据覆盖范围记录。
- 数据更新时间记录。
- 缺失区间检测。
- 数据补齐。
- 重复记录处理。
- 缓存异常标记。

## 8.5 缓存读取规则

当用户查询行情时：

1. 查询本地数据是否覆盖请求范围。
2. 判断对应交易日是否缺失。
3. 对缺失区间调用 AKShare。
4. 校验外部返回结果。
5. 写入新增或修正数据。
6. 返回符合请求范围的数据。

## 8.6 更新策略

建议：

- 历史较久的数据优先使用有效缓存。
- 最近交易日行情需要检查是否已经更新。
- 已确认的历史数据通常无需每次重新下载。
- 当数据源出现历史修订时，允许主动刷新缓存。
- 更新失败时不覆盖原本有效的数据。

## 8.7 一致性要求

行情记录至少应区分：

```
股票代码
交易日期
原始价格
数据来源
数据更新时间
```

前复权、后复权的数据需要明确复权来源或因子版本。

不同复权口径不能在缓存或计算时混用。

# 9. K 线周期与复权功能

## 9.1 功能编号

```
F05-K线周期`、`F06-复权切换
```

## 9.2 K 线周期

系统支持：

- 日 K。
- 周 K。
- 月 K。

用户切换周期后：

1. 更新 K 线数据。
2. 更新技术指标。
3. 更新对应的时间范围。
4. 保持当前股票不变。
5. 保持当前复权方式，除非用户主动修改。

## 9.3 复权类型

| 类型   | 标识 | 描述                 |
| ------ | ---- | -------------------- |
| 不复权 | none | 保留历史原始交易价格 |
| 前复权 | qfq  | 使用前复权口径       |
| 后复权 | hfq  | 使用后复权口径       |

默认值：`qfq`。

## 9.4 复权切换规则

用户切换复权方式后：

- 重新获取或计算对应价格序列。
- 重新计算依赖价格的技术指标。
- 更新图表。
- 更新 AI 分析上下文中的复权参数。
- 在分析结果中明确展示当前复权方式。

## 9.5 特殊处理

复权因子或历史复权序列可能随公司行为及数据源修订发生变化。

因此，历史分析结果应记录数据口径及对应的版本或获取时间，避免不同时间生成的历史报告难以核对。

## 9.6 分钟线外部查看

当用户要求查看分钟线时，系统应提供能够打开对应股票行情页面的外部链接。

要求：

- 使用可信的第三方行情平台。
- 股票代码与交易所匹配。
- 不生成未经验证的跳转地址。
- 不将分钟行情纳入本系统指标计算。
- 明确告知用户将访问第三方网站。

# 10. 技术指标分析功能

## 10.1 功能编号

```
F07-技术指标分析
```

## 10.2 功能描述

系统根据历史行情数据计算股票技术指标，用于图表展示及 AI 分析。

指标由 Python 后端计算，不由 DeepSeek 直接生成指标数值。

## 10.3 指标清单

| 指标 | 英文名称                              | 主要作用     | MVP 要求 |
| ---- | ------------------------------------- | ------------ | -------- |
| MA   | Moving Average                        | 简单移动平均 | 必须     |
| EMA  | Exponential Moving Average            | 指数移动平均 | 建议     |
| MACD | Moving Average Convergence Divergence | 趋势及动量   | 必须     |
| RSI  | Relative Strength Index               | 相对强弱     | 必须     |
| KDJ  | Stochastic Indicator                  | 随机指标     | 必须     |
| BOLL | Bollinger Bands                       | 波动区间     | 必须     |
| VOL  | Volume                                | 成交量分析   | 建议     |
| ATR  | Average True Range                    | 波动幅度     | 后续     |
| ADX  | Average Directional Index             | 趋势强度     | 后续     |
| CCI  | Commodity Channel Index               | 价格偏离     | 后续     |
| OBV  | On Balance Volume                     | 量价关系     | 后续     |
| WR   | Williams %R                           | 超买超卖     | 后续     |
| ROC  | Rate of Change                        | 价格变化率   | 后续     |
| BIAS | Bias Ratio                            | 均线偏离率   | 后续     |

## 10.4 MA 指标

用户可以选择：

- MA5。
- MA10。
- MA20。
- MA60。
- 自定义合理周期。

计算方式：

```
MA(N) = 最近 N 个有效收盘价的算术平均值
```

## 10.5 MACD 指标

建议采用常见参数：

```
fast = 12
slow = 26
signal = 9
```

输出：

- DIF。
- DEA。
- MACD 柱值。

MACD 柱值的倍数约定及 EMA 初始化方法应由技术设计统一定义，避免与不同平台的结果产生不必要的口径差异。

## 10.6 RSI 指标

建议支持常用周期：

- RSI6。
- RSI12。
- RSI24。

输出：

- RSI 数值序列。
- 对应指标参数。
- 指标计算有效区间。

## 10.7 KDJ 指标

建议默认参数：

```
N = 9
K平滑参数 = 3
D平滑参数 = 3
```

输出：

- K。
- D。
- J。

具体平滑算法由技术设计统一定义。

## 10.8 BOLL 指标

建议默认参数：

```
period = 20
std_multiplier = 2
```

输出：

- 中轨。
- 上轨。
- 下轨。

## 10.9 技术指标业务规则

1. 指标计算使用明确的行情周期。
2. 指标计算使用当前复权口径。
3. 参数必须经过合法性校验。
4. 必须考虑计算指标所需的预热数据。
5. 无足够样本时返回缺失状态。
6. 不能把不可计算值显示为有效指标。
7. 不同指标的计算方法应有统一定义。
8. AI 只解释业务工具返回的实际计算结果。

## 10.10 指标分析示例

用户输入：

```
分析贵州茅台最近三个月的 MACD 和 RSI。
```

系统执行：

```
识别股票
   ↓
查询历史行情
   ↓
获取计算所需预热样本
   ↓
计算 MACD
   ↓
计算 RSI
   ↓
整理结构化指标结果
   ↓
AI 解读指标关系
   ↓
显示指标图表
```

查询贵州茅台最近一年的历史走势。

## 12.5 AI 处理流程

```
用户输入自然语言
         ↓
DeepSeek 识别用户意图
         ↓
LangGraph 生成任务执行计划
         ↓
检查需要调用的业务工具
         ↓
调用一个或多个工具
         ↓
获取结构化执行结果
         ↓
检查数据是否充分
         ↓
DeepSeek 生成分析说明
         ↓
输出文本、指标和图表信息
```

## 12.6 AI 职责

AI 负责：

- 识别用户意图。
- 解析股票和分析条件。
- 决定调用哪些工具。
- 组织多步骤任务。
- 整理工具返回的数据。
- 解释指标和走势。
- 形成结构化分析。
- 表达不确定性。

AI 不负责：

- 编造实时或历史价格。
- 编造财务数据。
- 自行生成技术指标数值。
- 代替后端执行 SQL。
- 绕过工具权限。
- 保证未来股价走势。
- 自动执行证券交易。

# 14. AI 分析结果功能

## 14.1 功能编号

```
F11-AI分析结果
```

## 14.2 设计目标

分析结果不仅包含自然语言，还应包含结构化内容，方便前端展示为卡片和图表。

## 14.3 分析结果结构

建议包含：

### 1. 股票与查询范围

- 股票代码。
- 股票名称。
- 时间区间。
- 周期。
- 复权方式。

### 2. 客观事实

例如：

- 最近有效交易日的收盘价。
- 区间价格变化。
- MA20 实际计算值。
- MACD、RSI 等指标数值。

### 3. 分析推断

基于事实讨论：

- 趋势特征。
- 指标变化。
- 指标之间是否一致。
- 可能的不同解释。

### 4. 情景假设

说明在不同市场条件下可能出现的情景，不把假设描述为预测事实。

### 5. 分析局限

例如：

- 不包含实时价格。
- 数据仅截至上一交易日。
- 部分指标缺失。
- 历史数据不保证未来表现。

### 6. 风险说明

提示用户关注市场波动、数据局限和分析不确定性。

### 7. 数据来源

明确行情、指标及基本资料来源。

## 14.4 分析结果示意

```
股票分析：贵州茅台（600519）

分析周期：日线
复权方式：前复权
分析区间：YYYY-MM-DD 至 YYYY-MM-DD

一、客观数据
- 最近有效收盘价：由行情工具返回
- MA20：由指标工具计算
- MACD：由指标工具计算
- RSI：由指标工具计算

二、技术分析
根据已计算的指标讨论近期走势和动量表现。

三、分析局限
本分析基于指定时间范围内的历史数据，
无法保证未来价格变化。

四、数据来源
AKShare 对应数据接口
实际数据截至日期：YYYY-MM-DD
```

上面是输出结构示例，不代表真实行情结果。

## 14.5 风险控制规则

- 事实与推断分开。
- 不确定性明确说明。
- 缺失数据明确说明。
- 避免绝对化预测用语。
- 不使用未经验证的“AI 可信度百分比”。
- 不以风险声明代替必要的上线合规审查。

来自行情数据、财务数据或技术指标计算。

# 34. 功能设计总结

股票查询 ChatBI 平台采用以自然语言交互为入口、以固定业务工具为执行核心、以真实股票数据为分析基础的产品设计方案。

平台长期功能包括：

- 股票信息查询。
- 历史行情分析。
- 技术指标。
- 交互式可视化。
- AI 多工具分析。
- 股票比较。
- 自然语言选股。
- 财务与估值分析。
- 用户及会话管理。
- 自选股。
- 会员积分。
- 综合运营后台。
- 数据质量和后台任务管理。

第一阶段 MVP 聚焦完成以下核心流程：

```
用户输入
   ↓
识别股票及分析意图
   ↓
查询 AKShare / SQLite 行情数据
   ↓
计算所需技术指标
   ↓
LangGraph 调用业务工具
   ↓
DeepSeek 解释分析结果
   ↓
展示结构化分析卡片
   ↓
展示交互式 K 线及指标
   ↓
提供数据来源和风险说明
```
