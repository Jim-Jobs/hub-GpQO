## 1. 项目背景与问题

### 1.1 背景

企业内部数据分散在多张关系型数据库表（订单、用户、商品、库存等）中。传统取数流程存在明显瓶颈：

- **依赖数据团队**：业务人员提需求 → 排期 → 数据/BI 同学写 SQL → 返回结果，链路长、响应慢。
- **SQL 门槛高**：一线运营、产品、管理层不具备写 SQL 的能力，无法自助取数。
- **口径不一致**：同一指标多人各自手写 SQL，统计口径容易漂移，导致「同一个问题两个答案」。
- **重复劳动**：大量临时性、探索性的查询需求（TopN、占比、趋势）本质是套路化 SQL，不应每次都由人来做。

### 1.2 问题定义

> 如何让非技术用户**用自然语言直接与数据对话**，系统自动完成「选表 → 生成 SQL → 校验 → 执行 → 解释结果」，从而把取数从「数天」缩短到「秒级」，同时保证结果**可执行、可校验、可解释、可追溯**。

---

## 2. 项目目标

### 2.1 业务目标

| 目标 | 说明 | 衡量方式 |
| --- | --- | --- |
| 降低取数门槛 | 业务人员无需 SQL 即可取数 | 自助取数占比提升至 60%+ |
| 缩短取数周期 | 从「天级」到「秒级」 | 平均取数时长下降 90%+ |
| 降低人力成本 | 释放数据/BI 团队的重复劳动 | 数据团队处理临时查询人天下降 |
| 提升数据利用率 | 让沉睡的数据被更多人用起来 | 周活用户数、周查询次数 |

### 2.2 产品目标

1. 提供**自然语言 → 数据结果**的一站式对话体验。
2. 回答结果附带**图表可视化**和**可解释的 SQL 生成过程**，建立用户信任。
3. 支持**多轮追问**与上下文理解（「那按月呢？」「换成 2024 年」）。
4. 保证结果**安全、准确、可审计**。

## 3. 目标用户与使用场景

### 3.1 目标用户

| 用户角色 | 特点 | 核心诉求 |
| --- | --- | --- |
| 业务运营/市场 | 不懂 SQL，高频临时取数 | 快速得到口径正确的数据 + 图表 |
| 产品经理 | 需要数据支撑决策 | 探索性查询、看趋势和占比 |
| 管理层 | 只看结论 | 指标概览、自然语言问询 |
| 数据分析师 | 会 SQL，追求效率 | 快速生成初版 SQL，减少手写 |

### 3.2 典型场景

- **场景 A**：「上个月手机类目销量前 10 的商品是哪些？」→ 返回榜单 + 柱状图。
- **场景 B**：「各区域销售额占比」→ 返回饼图 + 明细。
- **场景 C**：「最近 3 个月销售趋势」→ 返回折线图 + 环比分析。
- **场景 D**：「这个季度的会员复购率是多少？」→ 复杂口径（涉及多表 join + 计算），系统给出 SQL 口径说明。

## 4. 项目范围

### 4.1 本期（MVP）

- 单数据源接入（关系型数据库，如 MySQL / SQLite / PostgreSQL）。
- 单轮 + 基础多轮自然语言问答（NL2SQL）。
- 核心 SQL Agent 流水线：数据库解析 → 表选择 → SQL 生成 → 校验 → 改写 → 执行 → 结果汇总。
- 结果可视化（表格 + 柱状图 / 折线图 / 饼图）。
- SQL 生成过程透明化（可查看生成的 SQL）。
- 基础权限与数据安全（只读、字段级脱敏）。

### 4.2 后续（二期）

- 多数据源 / 多库联邦查询。
- 指标口径沉淀（语义层：指标字典、维度字典）。
- RAG 检索历史相似问答，提升准确率与缓存命中。
- 主动预警与订阅推送（定时任务）。
- 多模态输入（上传表格、语音提问）。
- 评测体系与线上反馈闭环。

---

## 5. 核心价值主张

1. **快**：秒级响应，替代数天排期。
2. **准**：SQL 校验 + 改写 + 结果校验，降低 LLM「幻觉 SQL」风险。
3. **懂**：可解释——展示 SQL、展示用了哪些表，用户可追溯、可复核。
4. **稳**：只读访问 + 权限控制 + 审计日志，保证数据安全。

## 6. 成功指标

### 6.1 北极星指标

> **每周有效自助查询次数**（用户成功获得结果且未弃用的查询）。

### 6.2 过程/护栏指标

| 维度 | 指标 | 目标 |
| --- | --- | --- |
| 准确率 | SQL 执行成功率 | ≥ 95% |
| 准确率 | 结果正确率（抽样人工评测） | ≥ 90% |
| 体验 | 平均端到端响应时长 | ≤ 5s（流式输出） |
| 体验 | 多轮对话上下文正确率 | ≥ 85% |
| 留存 | 周活用户数 / 周留存率 | 持续上升 |
| 安全 | 越权查询拦截率 | 100% |

## 8. 风险与约束

| 风险 | 描述 | 缓解措施 |
| --- | --- | --- |
| LLM 幻觉 | 生成不存在字段/表、错误口径 | 数据库解析注入真实 schema；校验+改写闭环；结果合理性校验 |
| 数据安全 | 敏感字段被查询导出 | 只读账号、字段级权限、敏感字段脱敏、审计日志 |
| 口径漂移 | 同名指标口径不一致 | 语义层/指标字典统一口径 |
| 模型稳定性 | 不同模型/版本输出不稳定 | 固定输出结构（JSON/SQL）、温度调低、评测回归 |
| 复杂查询 | 多表 join、窗口函数易错 | 分步推理、提供外键关系、失败重写 |
