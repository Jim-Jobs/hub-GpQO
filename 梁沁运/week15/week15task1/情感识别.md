# 项目开发指南：情感陪伴 AI 微服务系统

## 一、 项目背景与核心目标
本项目是一个情感陪伴 AI 应用，采用**前后端分离**的微服务架构。
业务逻辑：接收用户输入 -> 情感二分类（positive/negative） -> 正向输出鼓励话术，负向输出排解话术。
系统提供两种底层引擎供用户选择：LangGraph 和 OpenAI-Agents。用户可以在前端通过下拉菜单选择使用哪种引擎获取结果。系统包含三个独立部分：一个前端页面，两个独立的后端微服务。

## 二、 全局架构与通信契约
1. **前端（Frontend）**：运行在本地，通过下拉菜单选择底层引擎，根据选择向不同端口发送 HTTP POST 请求。
2. **后端 A（LangGraph Service）**：运行在 `127.0.0.1:8000`，采用 LangGraph 框架实现。
3. **后端 B（Agents Service）**：运行在 `127.0.0.1:8001`，采用 OpenAI-Agents SDK 框架实现。
4. **API 契约（两端必须完全一致）**：
   - 请求体 JSON：`{"user_input": "用户输入的文本"}`
   - 响应体 JSON：`{"sentiment": "positive/negative", "response": "AI生成的话术"}`
   - **技术栈约束**：后端统一使用 FastAPI，统一使用**同步调用**（不使用 async/await），并必须配置 `CORSMiddleware` 允许跨域。

## 三、 环境变量与密钥管理（极其重要）
所有涉及 API Key 的地方，**绝对禁止硬编码**，必须通过环境变量读取。
请在两个后端目录下分别创建 `.env` 文件，并包含以下内容：
```env
SILICONFLOW_API_KEY=your_api_key_here
SILICONFLOW_MODEL=deepseek-ai/DeepSeek-V4-Flash
SILICONFLOW_BASE_URL=https://api.siliconflow.cn/v1
代码中必须使用 python-dotenv 加载环境变量。

四、 后端 A：LangGraph 服务目录与规范
text
langgraph_service/
├── schemas.py         # 契约层
├── nodes.py           # 逻辑层
├── workflow.py        # 编排层
├── main.py            # 网络层
└── requirements.txt
1. 文件职责与约束
schemas.py：

定义 ChatRequest 和 ChatResponse（Pydantic 模型）。

定义 AgentState（TypedDict），包含 user_input, sentiment, response。

nodes.py：

仅在此文件中调用大模型，且只允许在以下三个函数中发起请求。

analyze_sentiment：调用 SiliconFlow 接口，判断情感是 positive 还是 negative，返回 {"sentiment": ...}。

generate_encouragement：读取 user_input，生成鼓励，返回 {"response": ...}。

generate_console：读取 user_input，生成排解，返回 {"response": ...}。

workflow.py：

实例化 StateGraph(AgentState)。

添加上述三个节点。

使用 add_conditional_edges 实现路由：读取 sentiment，如果是 positive 走鼓励节点，negative 走排解节点。

编译并导出全局变量 app_graph。

main.py：

初始化 FastAPI，挂载 CORS。

写 @app.post("/chat") 接口，内部使用 app_graph.invoke({"user_input": ...}) 获取结果并返回。

启动端口为 8000。

五、 后端 B：OpenAI-Agents 服务目录与规范
text
agents_service/
├── schemas.py         # 契约层
├── agents.py          # Agent 定义层
├── workflow.py        # 编排层
├── main.py            # 网络层
└── requirements.txt
1. 文件职责与约束
schemas.py：同 LangGraph 版本的请求响应模型。此外，需定义一个 SentimentOutput（Pydantic 模型），包含 sentiment: Literal["positive", "negative"]，用于分类 Agent 的结构化输出。

agents.py：

必须引入 from agents import set_default_openai_api, set_tracing_disabled, Agent, OpenAIChatCompletionsModel。

在模块顶部执行：set_tracing_disabled(True) 和 set_default_openai_api("chat_completions")。

实例化 SiliconFlow 兼容的 OpenAI Client。

定义三个独立的 Agent，分别负责三项功能：

sentiment_agent：情感识别，绑定 output_type=SentimentOutput。
encourage_agent：生成鼓励话术，普通文本输出。
console_agent：生成排解话术，普通文本输出。
三个 Agent 的模型均指向 deepseek-ai/DeepSeek-V4-Flash。

workflow.py：

不使用状态图，也不使用 Agent Handoff。编写一个普通的同步函数 run_workflow(user_input: str)。

内部逻辑：使用 Runner.run_sync 先执行 sentiment_agent，拿到结构化结果 final_output.sentiment。

使用 Python 原生的 if-else 路由：根据 sentiment 判断，用 Runner.run_sync 执行 encourage_agent 或 console_agent。

返回 ChatResponse。

main.py：

初始化 FastAPI，挂载 CORS。

写 @app.post("/chat") 接口，内部调用 run_workflow。

启动端口为 8001。

六、 前端规范 (Frontend)
采用纯 HTML + 原生 CSS + 原生 JS，不使用前端框架。

界面包含一个下拉选择器（引擎选项：LangGraph / OpenAI-Agents）。

包含输入框和发送按钮。

发送逻辑：

若下拉框选择 LangGraph，发送 POST 到 http://127.0.0.1:8000/chat。

若下拉框选择 OpenAI-Agents，发送 POST 到 http://127.0.0.1:8001/chat。

请求头设置 Content-Type: application/json。

收到响应后，在页面上渲染情感倾向和 AI 回复。

七、 开发执行顺序与要求
先写后端代码：请先完整生成 langgraph_service 和 agents_service 两个目录下的所有代码（暂不生成前端 HTML）。

严格按照上述目录规范，禁止把代码揉进单一文件。

务必在 requirements.txt 中包含：fastapi, uvicorn, pydantic, python-dotenv, langgraph, langchain-openai, openai-agents。

为代码提供清晰的中文注释，特别是哪里对应“进程 1（识别）”，哪里对应“进程 2（生成）”，以及条件路由在哪里。

代码需保持整洁、生产级风格，预留好读取 .env 的接口。
